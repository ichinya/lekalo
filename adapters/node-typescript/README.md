# `lekalo-target-node-typescript` — TypeScript target adapter (issues #43/#44)

The `lekalo.target/v1` protocol kernel (issue #43) plus the vendored
TypeScript symbol scanner (issue #44) in one committed single-file
artifact. The kernel itself uses only Node built-ins
(`node:crypto`, `node:fs`, `node:path`); the scanner uses the
**vendored** TypeScript compiler embedded in the artifact. No external
runtime installation, no `NODE_PATH`, no project `node_modules` — one
physical file.

## Invocation

```sh
# production protocol process: exactly one request, exactly one response
node adapters/node-typescript/adapter.mjs
# request over stdin, or when core declares only the file transport:
node adapters/node-typescript/adapter.mjs --lekalo-request-file <PATH>

# trusted launch input (the ONE way to root the adapter at a project and
# enable the scanner; must directly follow the entry argument):
node adapters/node-typescript/adapter.mjs --lekalo-project-profile-json '<compact-json>'

# local metadata probe (NOT part of the wire protocol; only as the sole
# argument):
node adapters/node-typescript/adapter.mjs --version-json
```

Core launches the adapter as a direct argv vector —
`AdapterCommand { program: node, args: [adapter.mjs, …] }` — never through a
shell or a package manager. The confined runtime copies the executable
and exactly the first-argument script into its private view; relative
sibling imports and ambient `node_modules` would break confinement,
which is why this adapter is deliberately a single file: the compiler,
its standard-library declarations, and the kernel live inside it.

## The launch profile (root authority)

The wire's resolved profile is a token plus digest/capability pairs — it
carries **no read roots**. Roots come exclusively from the
`--lekalo-project-profile-json` launch input: one bounded (16 KiB),
strict-decoded JSON document shaped exactly like the internal
`ResolvedProjectProfile` (id, mode, target, readRoots, exclusions,
targetResolution, provenance). It is owned by the caller of the
`AdapterCommand`, never read from the wire, the environment, or the
project. Without it, the adapter describes kernel-only and refuses
everything else — there is no `src/**` fallback, no discovery, no
profile file path on the wire.

Before any extension dispatch, the kernel enforces the F1 binding:
the request profile id and target must equal the trusted profile's, and
a claimed `profile_digest`/`profile_capabilities` pair must match the
trusted `targetResolution` snapshot exactly — digest equality, deep
canonical capability-set equality, both members present or both absent.
Mismatches are structured `profile-binding-mismatch` refusals; no read
counter moves.

## Vendored compiler bundle

`adapter.mjs` is GENERATED by `build.mjs`; verify with
`node build.mjs --check` (rebuilds in memory and refuses byte drift —
repeated builds are byte-identical: no paths, timestamps, or traversal
order). The build pins `typescript@5.9.3` and `esbuild@0.25.12`
exactly (`package-lock.json`; provision once with
`npm ci --prefix adapters/node-typescript --ignore-scripts --no-audit
--no-fund`, development/CI only — never during scans). The artifact
embeds the compiler API plus every `lib.*.d.ts` of the same pin as a
sorted string map: standard libraries are type context only, never
project symbols. Legal attribution: `THIRD_PARTY_NOTICES.md` and the
artifact header.

## The scanner (issue #44)

Program/TypeChecker-based semantic indexing inside the kernel's read
view:

- restricted CompilerHost: lookups are answered only from the
  pre-enumerated inventory (scope/exclusion checks enforced by the
  kernel read view) or the embedded libraries; no `ts.sys`, no
  wildcard filesystem reads, no environment. Symlinks anywhere in a
  staged root are fatal; `vendor/**`, `node_modules/**`, `dist/**`
  and friends are pruned before any stat.
- native identity: `ts1-` + sha256 over the domain-separated tuple
  (package locator, module path, lexical qualified name, declaration
  family, slot) — stable under body edits, moves on rename, never
  reusing compiler object ids or line numbers.
- structural signature digests over ordered overload sets, parameter
  shapes, nullability, type arguments; aliases and re-exports are
  alias edges, merged declarations one symbol, overloads stored whole.
- references (imports/calls) as typed rows; unresolved targets are
  recorded as uncertainty, never guessed.
- routes/tests via explicit rule plugins with confidence and
  provenance; dynamic paths/names are uncertainty, never fabricated.
- `any`/`unknown` surfaces, unresolved imports, dynamic calls:
  recorded uncertainty that never becomes an optimistic pass.
- incremental session: reuse keyed on the complete input manifest;
  cold and warm scans of the same bytes are byte-identical.

Wire projection: scan entries carry bounded `detail`
(`{s,n,l,q}`) plus the v0.3.1 typed `evidence` member (structural
signature digest, up to eight typed reference rows). Uncertainty in
the index keeps the outcome honestly `partial` — a partial scan is an
in-envelope error, never a silently complete receipt.

## Operation table

| Operation | Posture | Owner of the real behavior |
| --- | --- | --- |
| `describe` | Implemented. No project/source/config reads or writes. | Kernel, permanently. |
| `scan` | Implemented (issue #44) with the launch profile: real Program/TypeChecker indexing. Without the launch profile: `unsupported`, not advertised. | #44 |
| `bind` | Unsupported/undeclared. Profile validation is not binding. | #42 registry flow (`lekalo bindings propose/confirm/audit`), not an adapter RPC. |
| `validate` | Unsupported/undeclared. Needs IR; not a profile RPC. | Later semantic/target validator owner. |
| `verify` | Unsupported/undeclared; test-only runner injection exercises framing without spawning commands. | #48 (+#47 scenarios). |
| `generate` | Unsupported/undeclared for dry-run and apply. No fake plan. | #45–#47 after #40. |
| `plan-clean` | Unsupported/undeclared. No inferred deletions. | Generation lifecycle owner. |
| `clean` | Unsupported/undeclared, even with a plausible plan id. | Generation lifecycle owner. |

A direct valid request to an unavailable operation returns one valid
`status: "error"` response with `error.class: "unsupported"`, fixed code
`operation-unsupported`, fixed message, `partial: false`, and no
`result`/`writes`/`progress`. Core normally refuses an undeclared
operation **before launch** (`target.capability-unsupported`, exit 4);
a child-reported unsupported error instead maps through
`target.operation-failed` to invalid (exit 1). The two CLI statuses are
intentionally not identical.

## Identity and runtime versions

- Adapter id: `lekalo-target-node-typescript`; version `0.3.1` (the
  reserved product version — not a protocol version); digest `sha256:`
  over the exact launched entry bytes, echoed on every response.
- Protocol: `lekalo.target/v1`, the sole supported version `0.3.1`
  (exact membership; no ranges, aliases, or fallbacks). The v0.3.1
  contract additively extends scan entries with the typed `evidence`
  member; the v0.2.16 documents are superseded, never edited.
- Compiler: `typescript 5.9.3` (vendored), `esbuild 0.25.12`
  (build-only), reported by `--version-json`.
- **Node runtime versions are not in the handshake.** The describe
  response has no slot for them (and rejects `result`/`progress`
  there). They are reported by the local `--version-json` probe
  (exact `process.versions.node`, adapter id/version/entry digest,
  compiler pins) and carried in internal evidence.

Every root is validated **lexically** (no absolute/drive/UNC/device/
URI spellings, no `..`/`.` segments, no backslashes, percent escapes,
colons/control characters, trailing dots/spaces, DOS devices,
short names, overlong paths, uppercase or whitespace segments; `.`
is only the protocol project root, never an all-files root) and then
**physically** before any extension callback runs. One invalid root —
first or last — prevents every scanner invocation and yields one honest
`invalid` error. Component walk: every path component from the trusted
root to the entry is lstat-inspected, so inside-pointing intermediate
links are refused exactly like outside-pointing ones; Windows junctions
report as symlinks through `lstat().isSymbolic()` (the removed
`fileAttributes` reparse checks were dead code on every supported
Node).

## Standalone synthetic limitations

The production artifact without the launch profile describes and
refuses everything else. The committed fixtures under
`tests/fixtures/node-typescript-kernel/` (kernel) and
`tests/fixtures/node-typescript-scanner/` (scanner) are exclusively
synthetic (`public-fixture`): profiles, callback results, and evidence
are invented fixture vocabulary; fixture `package.json` files carry
poison scripts that must never run (and never do). The scanner suites
materialize those fixtures into disposable temp projects and drive the
production artifact end to end.

## Extension interface (#48 attaches here)

```text
createKernel({ identity?, resolvedProjectProfile?, extensionRegistry?, localEvidenceSink? })
  describe()
  dispatch(validatedRequest, trustedExecutionContext)

ExtensionDescriptor = {
  id, version, operations, namedCapabilities?, acceptedIrVersions?,
  invoke({ operation, request, profile, readView, cancellation, limits })
}
InternalOperationOutcome = { state: complete|partial|unknown|unsupported|failed,
                             data?, evidence?, diagnostics? }
```

Extensions are registered explicitly — never discovered from a project
or profile. Descriptor compatibility is validated at registration
(duplicate ids/operation claims refuse); the advertised capability map
is computed from installed, validated implementations only, and
`describe.ir_versions` is the sorted unique union of the enabled
descriptors' accepted versions. All roots are validated before
`invoke`; every returned value is normalized at one boundary; a throw,
rejection, or malformed result becomes an honest `infrastructure`
error, never a success. The boundary is an extension seam, **not** an
isolation boundary against malicious imported JavaScript.

Evidence (revision, provenance, confidence, freshness, full source
spans, original local references, dynamic candidate sets) is preserved
completely in the internal outcome and the local-only sink. The public
wire carries only what the closed contract can represent; partial,
unknown, and ambiguous outcomes surface as honest in-envelope errors
(`partial: true` where partial work exists — there is no invented
`status: "partial"`), unrepresentable values are refused rather than
truncated (a complete inventory over the 10,000-entry wire bound is
refused, never sliced), and a `truncated` scan result is never
projected, because the current merging caller ignores the flag.

## Errors

| Cause | Class | Fixed code |
| --- | --- | --- |
| Unimplemented operation | `unsupported` | `operation-unsupported` |
| Profile/request invalidity | `invalid` | `profile-invalid` |
| Root lexical/physical failure | `invalid` | `root-invalid` |
| F1 binding mismatch | `invalid` | `profile-binding-mismatch` |
| Extension threw / malformed output | `infrastructure` | `extension-failed` |
| Controlled conflict / partial outcome | `conflict` | outcome-specific bounded token |

Wire bounds mirror the contract: code 1–128 code points, message
1–256, detail ≤ 16 entries of ≤ 128. No raw JS stacks, host paths, or
untrusted strings leave the process; richer diagnostics stay in the
local-only evidence when authorized.

## Boundary decisions

1. **Internal vs external evidence.** Full extension evidence is
   preserved internally and locally; the process `Evidence` (adapter
   identity, optional plan id) is unchanged. The v0.3.1 scan-entry
   `evidence` member (issue #44) is the reviewed transport extension
   that carries signature digests and typed references to the core.
2. **Root authority.** Roots come only from the trusted launch input
   (or the in-process injected profile); the wire profile resolution
   stays digest + capability pairs, and a claimed resolution must
   exactly match the trusted snapshot (F1) before dispatch.
3. **Runtime metadata location.** Node version lives in the local
   `--version-json` probe and internal evidence, not in `describe`.
4. **Conformance scope.** The adapter passes applicable default-profile
   rows; strict `capability.surface` fails **by design** — the eight-
   operation surface belongs to later issues. With the launch profile,
   `process.cancellation` genuinely passes (scan is a cancellable
   operation). No fake operations are advertised to obtain a badge.
