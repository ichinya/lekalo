# Tutorial: the Laravel + Vue greenfield pilot path

The concrete, runnable walk of the pilot path
(`docs/m5/roadmap.md`) over the committed fixtures: from the neutral
planner Model to the maintained Vue screen, with every gate green at
the end. Every command runs from the repository root; provisioning
happens once, outside verification.

You will not write the backend by hand: the Model is the source of
truth, the generated surface is regenerated byte-stably, and the code
you maintain is the deliberately small set of port bodies, policies,
middleware, and the screen — the #50/#53 measured split.

## 0. Provision once (outside verification)

```sh
# PHP >= 8.3 with mbstring, openssl, pdo_sqlite, sqlite3, tokenizer,
# xml, dom, xmlwriter, ctype, fileinfo, iconv, session
composer install --no-interaction --prefer-dist --no-scripts \
  --working-dir tests/fixtures/php-laravel/planner

# Exact pinned toolchain for the contract + ui gates, outside the checkout
npm install --prefix "$RUNNER_TEMP/lekalo-ajv" --ignore-scripts --no-audit --no-fund \
  ajv@8.17.1 @seriousme/openapi-schema-validator@2.8.0 typescript@5.9.3 @vue/compiler-sfc@3.4.38
export NODE_PATH="$RUNNER_TEMP/lekalo-ajv/node_modules"

# Optional: the real Mago toolchain (checksum-pinned by
# adapters/php-laravel/mago-toolchain.lock.json); without it the fake
# suite still runs.
```

## 1. Start from the neutral Model

The planner Model lives in the routes-corpus model home
(`tests/fixtures/php-laravel/routes/model/lekalo/`): entities, scalars,
commands, queries, policies, events, endpoints, and scenarios — no
framework vocabulary anywhere. Prove that property:

```sh
node scripts/test-planner-model-neutrality.mjs
```

Read the focus command as a consumer would — one self-contained
document, no repository archaeology:

```sh
less docs/m5/issue-114/focus-task-capsule.md
```

## 2. Generate the Laravel surface (commands, queries, policies, storage)

The composed run plans types, operations, and routes in one authorized
join; the fixture's maintained boundary (`app/Lekalo`, the port bodies)
stays user-owned:

```sh
node scripts/test-php-laravel-operations.mjs   # 13 stages
node scripts/test-php-laravel-routes.mjs       # 9 stages, incl. the runtime battery
```

What you should internalize from the fixtures:

- every governed operation = one maintained port body + one container
  binding line; no hand-written controllers, request classes, or
  OpenAPI fragments;
- `declare(strict_types=1)`, final/readonly/typed everywhere; explicit
  transactions (the `TransactionPort` run wraps the body — the rollback
  guarantee is the wrapper's);
- no business logic in controllers, no hidden effects in observers, no
  facades in the portable core.

## 3. Serve the API and publish OpenAPI

The routes harness drives the real HTTP kernel through the generated
surface — including the planning battery (two users, carry-over byte
invariance, the one-active-focus constraint, stale compare-and-swap,
idempotency replay + conflict, the midnight boundary) — and proves the
published `openapi.json` is the same projection the code encodes. The
OpenAPI document is verbatim generated; drift is a typed finding.

## 4. Consume it from Vue through the generated client

```sh
node scripts/test-php-laravel-ui.mjs           # 6 stages
```

The maintained screen is `tests/fixtures/php-laravel/routes/ui/src/PlannerBoard.vue`.
It renders the declared queries' buckets, derives action availability
from the machine-readable predicates, applies the optimistic complete
with its declared rollback, and typechecks strict against
`ui/generated/planner.client.ts` — a byte-verified render of the same
join. Hand-duplicating DTOs is not just discouraged, it fails the gate.

## 5. Analyze and gate

```sh
node scripts/test-mago-integration.mjs --fake   # always
LEKALO_MAGO=/path/to/mago node scripts/test-mago-integration.mjs --real --require-available
node scripts/test-php-laravel-native-gates.mjs
```

The strict Laravel profile (`declare(strict_types=1)`, typed
signatures, no service locator) is enforced by Mago rules, not prose;
the native-gates harness proves the Composer gate planning under
process-launch-disabled interpreters.

## 6. Run the portable scenarios on Laravel

```sh
node scripts/test-php-laravel-scenario-tests.mjs   # 6 scenarios under Testo/Laratesto
```

The same six Scenario-IR documents the Node backend runs (authorization,
idempotency, transaction/rollback, error, happy, and the declared
unsupported race case). The scenarios are the *neutral* behavior
vocabulary; Laravel executes them through the generated Laratesto
tests against the real kernel and database.

## 7. Compare against the Node observed baseline

```sh
node scripts/test-php-laravel-parity.mjs \
  --emit-evidence tests/fixtures/pilot/equivalence/node-laravel.scenario-comparison.json
```

Both backends run the same corpus; the durable records normalize to
semantic `(step_id, observes, kind, outcome)` rows and must be
identical, including the shared lying-port failure control. The
removal gate that consumes this evidence is written down in
`docs/m5/issue-114-equivalence-report.md` — until every leg there is
green, the Node baseline stays exactly where it is.

## 8. The one-command battery

```sh
node scripts/test-pilot-laravel-vue.mjs
```

Nine legs, path order, fail-loud. If a leg refuses, fix that leg — do
not skip it; every leg is a CI gate on its own.
