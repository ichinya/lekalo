## 1. Existing generation seam and exact type inventory

`adapters/php-laravel/adapter.php` is a generated bundle. Edit sources through `adapters/php-laravel/build.php`, never the bundle by hand. The build embeds the Mago lock and the analyzer/strict-profile/kernel/scenario modules. `src/kernel.php::deterministic_generation` routes scenario inputs to `scenario_generation`; `kernel_artifact` handles migration inputs and otherwise emits a small kernel support file. Neither path is a general domain-type compiler. `src/scenario-map.php` and `src/scenario-emit.php::php_emit_scenario_tests` provide pure mapping/emission and ownership precedents, not a DTO generator.

The actual compiled contract is `dev.lekalo.ir@0.2.16`: `crates/lekalo-core/src/ir/mod.rs` defines `CompiledProject`, `Definition`, `TypeRef`, `Field`, `ScalarBase` and `Compilation::source_map`; `ir/canonical.rs` serializes it. There is no standalone `ir.schema` file in `contracts/`. The accepted source schema is `contracts/model.schema.v0.2.16.json`; consume compiled IR after core validation, never reparse source YAML in the adapter.

Input inventory and schema sections:

- Scalars: Model `$defs.scalarDefinition`, IR `definitions[kind=scalar].base` / `ScalarDef`. Closed bases are string, number, boolean, date, datetime, uuid, uri. No integer or decimal primitive exists. Opaque IDs are nominal scalar projections, not an `opaque-id` definition kind. UUID-backed `planner.task_id` and `notify.user_id` must remain distinct PHP types.
- Enums: `$defs.enumDefinition`, IR `EnumDef.values[].value/description`. Preserve the exact declared string values and order. Planner `planner.task_state` has `backlog`, `focused`, `done`.
- Value objects: `$defs.valueObjectDefinition` and `$defs.fieldList`, IR `ValueObjectDef.fields`. Planner `planner.due_window` contains required `from` and `to` references to `planner.due_date`.
- DTOs: `$defs.entityDefinition`, `$defs.commandDefinition`, `$defs.queryDefinition`, `$defs.eventDefinition`; IR `EntityDef.fields/identity`, `CommandDef.input`, `QueryDef.returns`, `EventDef.payload`. Generate entity snapshots, command inputs, declared query outputs and event payloads. An entity DTO is not an Eloquent model. Commands have no output field in this IR; do not invent one. Query inputs/pagination, when needed, come from the separately validated `contracts/query-model.schema.v0.2.16.json` attachment.
- Presence/null/list: `$defs.fieldDefinition` (`name`, `type`, `required`, `description`) and `$defs.typeExpression`, `typeExpressionLevel2/3/4`, `typeExpressionLeaf`; IR `Field.required` and `TypeRef::{Ref,List,Optional}`. Depth limit is four including the leaf. `Optional` means nullable, independently of field presence. `Field` has no default, regex, numeric range or arbitrary validation metadata slot.
- Result/error types: not new IR definition variants. `contracts/error-contract.schema.v0.2.16.json` binds `operation`, `kind`, `output`, `errors`; `output=null` denotes command unit. `contracts/error-registry.schema.v0.2.16.json` supplies `$defs.errorContract`, `operationErrorContract`, `payload`, `payloadField`, `sourceRange`, retry/effect/idempotency and public/private exposure. Its closed error union is the supported source of an operation-specific result projection.
- Map and arbitrary union/generic: absent from accepted Model/IR. They cannot be enabled by adding an adapter option that silently changes the Model grammar. Section 6 defines explicit refusal and a future representation proposal.
- Validation metadata: derive only declared presence, nullability, enum membership, scalar format and list element type. Rich constraints need a reviewed, typed attachment/Model successor; storage defaults or checks must not become DTO defaults/validators implicitly. `contracts/expressions.schema.v0.2.16.json` and `contracts/invariant-transition.schema.v0.2.16.json` are separate semantic contracts, not arbitrary `Field` attributes.
- Field/source trace: `Compilation::source_map` is a sibling of IR, not part of canonical semantic bytes. Entries carry logical `path`, optional `semanticId`, JSON `pointer`, `start`, `end`; see `docs/ir.md`. Model `commonFields` also supplies description, version, derived requirements and rename history. Field occurrences need owner ID plus pointer/name; do not pretend every field already owns a stable symbol ID.

Concrete shared input: `tests/fixtures/adapter-conformance/inputs/ir-minimal.json` contains Planner task/state/ID/text/date/window, focus command, count query, focused event, plus cross-module Notify user/ID/channel/command. The query named `count_focused` actually returns `planner.task_state`; its name does not authorize an integer mapping. The task has optional nullable `due` and optional non-null list `window`; the focused event has optional non-null `focused_at`.

Additional existing inputs: `tests/fixtures/ir/valid-full-kinds/ir.golden.json` exercises all kinds; `tests/fixtures/contracted/planner-slice/lekalo/modules/planner/entities.yaml` adds `planner.timestamp`; `tests/fixtures/transport-http/project/lekalo/modules/planner/entities.yaml` adds `planner.tenant_id`, and its `queries.yaml` includes `list_tasks` and `tasks_by_project`. These are different fixture slices, not interchangeable snapshots. Build and pin a single joined acceptance corpus rather than merge their conflicting definitions by name.

## 2. Proposed PHP constructs, profile and mapping

**Proposed baseline:** PHP 8.3, matching current CI, with all generated files declaring `strict_types=1`. Native string-backed enums preserve wire values; do not add `final`/`readonly` class modifiers to enum syntax. DTOs and immutable VOs are `final readonly class`; enum cases and generated identifiers are escaped through a deterministic naming policy. PHP supports string/int backed enums and explicit nullable/union declarations; these language features do not supply serialization policy. See [PHP backed enums](https://www.php.net/manual/en/language.enumerations.backed.php) and [type declarations](https://www.php.net/manual/en/language.types.declarations.php).

**Proposed generated classes:** `TaskState`, `TaskId`, `Text`, `DueDate`, `DueWindow`, `TaskDto`, `FocusTaskInput`, `TaskFocusedPayload` and operation-specific result classes. Use typed constructor promotion for already validated immutable values. Where normalization or presence checks are needed, use a typed factory/private constructor and explicit assignments; never validate after publishing a partially initialized DTO. No dynamic properties, magic getters/setters, service locator, framework hydration or `array<string,mixed>` contract surface. `readonly` is not deep immutability: nested values/collections must also be immutable by construction.

**Proposed scalar policy:** string/bool map to their corresponding PHP primitive inside nominal wrappers; number uses an explicit finite `int|float` codec without numeric-string coercion. Specify representable numeric bounds and reject loss of precision; do not silently convert large JSON integers to floats. UUID/date/datetime/URI are validated string-backed VOs by default, preserving agreed wire spelling. An explicitly configured library codec may wrap a pinned immutable date/UUID/decimal class. Library FQN, package/lock identity, accepted format, normalization and codec revision are mapping inputs. Missing codec support is unsupported. Decimal is permitted only for an explicitly designated string scalar; never reinterpret `number` or infer decimal from a field name.

**Proposed collection policy:** concrete immutable collection classes specialized per element type, with typed methods and `list<T>` PHPDoc over private validated storage. Null elements only where the nested type permits them; preserve order and distinguish empty list from empty object. PHP native `array` lacks an element type, so annotations alone do not replace runtime validation. Public DTO fields expose a typed collection, not raw associative arrays.

**Proposed presence policy:** four cases must survive decoding and encoding:

1. Required non-null: absent and null fail; constructor accepts `T`.
2. Required nullable: absent fails; explicit null succeeds; constructor accepts `?T`.
3. Optional non-null: absent succeeds; explicit null fails; use a concrete presence wrapper carrying absent or `T`.
4. Optional nullable: absent, null and `T` are distinct states in a concrete presence wrapper.

The **proposed** wrappers use controlled factories/accessors and private state so callers cannot construct contradictory presence flags. Do not use `isset` as a presence test or add `=null` to every optional constructor argument. Current Model fields have no default: no default is emitted. A future reviewed default declaration must specify absent-only application, retain explicit null policy, and define canonical re-encoding; it must not leak in from a database default or Laravel cast. Reject unknown default metadata now, and add a regression fixture for that refusal.

**Proposed namespace/file mapping:** managed root `.lekalo/generated/php-laravel/types/`, configurable namespace prefix defaulting to `Lekalo\Generated\Types`; semantic module becomes one namespace segment and remaining symbol segments determine the class stem. Example: `planner.task_id` maps to **proposed** `Lekalo\Generated\Types\Planner\TaskId` in **proposed** `.lekalo/generated/php-laravel/types/Planner/TaskId.php`. DTO role suffixes are fixed, not dependent on traversal order. Retain an explicit semantic-ID-to-FQN/path index; detect reserved names, normalization collisions, case-insensitive PHP/Windows collisions, path traversal and duplicate output paths before emitting any file. Resolve three-segment IDs explicitly and reject collisions instead of appending order-dependent numbers. Renames use Model identity/history, never class spelling as identity.

**Proposed autoload:** a deterministic generated class map under the managed root, with optional documented consumer PSR-4 registration. Do not rewrite a consumer's Composer manifest or execute Composer during compilation. Library selection and autoload setup are explicit provisioning concerns; test them in the fixture.

**Proposed serializer mapping shape** (closed, versioned adapter-owned sidecar; not fields added to existing IR): top-level contract/identity, adapter identity, Model/IR/profile/lock/transport/error digests, wire dialect, then semantic-ID-sorted type entries. Each entry has semantic ID, FQN, artifact path, kind, codec, and ordered field rows containing owner ID, source pointer, model field name, PHP property, exact wire name, type reference, presence, nullable flag and public/private exposure. Defaults are absent until supported by an owning contract. Emit a matching typed codec per DTO; use an internal validated JSON-value tree/closed shapes at the parser boundary, never a mixed array as the public API. Optional **proposed** validation attributes are descriptive mirrors of this mapping, not a replacement for codec checks or a hidden framework execution path.

## 3. Ownership and custody: reuse #56 without conflating mechanisms

Existing custody is spread across `src/kernel.php::{scenario_generation,apply_writes,plan_clean_response,clean_response,delete_write}`, `src/scenario-emit.php::php_emit_scenario_tests`, `crates/lekalo-core/src/orchestration/generate.rs`, `crates/lekalo-core/src/artifacts/` and `crates/lekalo-core/src/target_protocol/{plan.rs,scopes.rs,transport.rs}`. Publication belongs to the core plan/apply authority, not an emitter writing the user's filesystem.

- **Managed, proposed mapping:** generated lifecycle, deterministic bytes/digests, approved generated root, drift check and scoped clean. Existing artifact manifests use `contracts/artifact-manifest.schema.v0.2.16.json`; retain the plan/lock/input revision binding and refusal on conflicting maintained content. New type output must not suppress existing scenario/migration output or erase their manifest entries.
- **Scaffold-once, proposed mapping:** explicitly declared consumer source root and namespace, created once then maintained by the user. Existing scenario files set `frozen=true` and a managed map marker; `scenario_generation` skips a frozen file when its marker exists, including when the maintained file was deleted. Missing scaffold is a verification finding, not permission to recreate it. New DTO scaffolds must refuse a pre-existing unowned path even without a marker, and preserve edited files on regenerate/clean.
- Existing `orchestration/generate.rs::lifecycle_for` is path-specific: `tests/lekalo/` non-map files become scaffolded. Existing `PHP_SCAFFOLD_SCOPE` is `tests/lekalo/scenario-tests/**`. **Proposed change:** add an explicit, validated type-scaffold policy and lifecycle recognition in both adapter and core; a flag in the emitter alone cannot protect a class under an arbitrary application directory. Marker deletion/corruption and source deletion must be adversarial tests; a marker alone must never grant overwrite authority.
- `retained_artifact()` currently matches `/migrations/`: it protects published migrations and their ledger from generic clean and rewrite. It is not the scaffold-once switch and should not be broadened to all DTOs. Migration history remains append-only; managed types remain regenerable. This corrects a possible conflation of #57 retention with #56 freeze semantics.
- **Checked binding, proposed mapping:** emit no replacement class and perform read-only conformance of declared semantic ID/FQN/path against observed source and expected shape. Existing `PHP_OBSERVED_INDEX_PATH` convention is `.lekalo/import/observed/index.json`; `php_join_checked_bindings` joins its `test_bindings` against scenario checked bindings and reports missing/ambiguous/stale claims. It does not check class constructors, field types, codecs or enum values. It also returns no findings when the index is absent: that permissive scenario helper is not sufficient proof for a required checked-type binding.

Existing `crates/lekalo-core/src/contracted/mod.rs::{parse_declaration_bytes,check,support}` and `contracts/contracted-declaration.schema.v0.4.0.json` supply maintained declarations/registry custody. `contracted/types.rs::SignatureEvidence` describes operation inputs/output/reads, not a full class-property schema; `SupportArtifact` and `Provenance` bind support paths/digests and adapter/revision. **Proposed extension:** a closed versioned class-shape evidence record (constructor/property visibility and types, presence, enum values, codec contract, source fingerprint, provider/config digests) joined to the declared ID. Missing/stale provider evidence must return unsupported or missing, never conformant. Check signature compatibility plus executable codec vectors; arbitrary PHP semantic equivalence is not promised. Keep generated support within the existing `.lekalo/generated/**` contracted boundary, with maintained class source outside ownership transfer.

Reuse existing `contracted/types.rs::ShapeEvidence` first: it already carries entity/VO fields (`SignatureField` name/type/required), scalar base and enum values. `contracted/check.rs::{canonical_shape,shape_matches}` compares those claims to compiled IR. The proposed native class evidence supplements this canonical shape with observed PHP facts; it does not replace it with a second semantic type model. The existing check deliberately permits a missing shape claim, so the proposed strict checked-type gate must require it explicitly. Existing `SymbolKind` includes entity/scalar/enum/value-object but not event; checked event-payload support requires a reviewed extension or an explicit unsupported result, not pretending an event is an entity.

## 4. Mago gate: existing wiring and remaining proof

Existing integration is real code: `adapters/php-laravel/src/analyzer.php::{Analyzer,MagoEvidenceAnalyzer,FakeAnalyzer,mago_decode_receipt,mago_check_compatibility}`; `src/kernel.php::{scan_response,validate_response,verify_response}` consume staged evidence. The adapter remains subprocess-free. `adapters/php-laravel/mago-toolchain.lock.json` pins Mago `1.0.0`, platform archive/binary checksums and reporting commands; `build.php` embeds the lock. Do not replace it with moving upstream documentation or invoke ambient tools inside confined generation.

`src/strict-profile.php::STRICT_RULES` defines strict-types, final-readonly-profile, no-dynamic-members, no-service-locator, no-magic-domain-state and explicit-types. Important limits visible in code:

- `strict_predicate_final_readonly` checks final/abstract/extensible modifiers, not complete readonly or immutable-property semantics; its class-like inventory includes enums/interfaces. Native enums must not be given illegal class modifiers to appease this predicate; special handling needs proof.
- `strict_predicate_unavailable` leaves service-locator, magic-state and explicit-type predicates unsupported. `no-variable-variable`, used for the dynamic row, is not a complete no-dynamic-properties proof.
- `strict_map_lint_row` treats a matching diagnostic as coverage; absence is unsupported. Therefore a clean lint result alone cannot establish rule execution. **Proposed improvement:** bind explicit rule-run coverage to the receipt and add positive/negative coverage fixtures before claiming all profile rules pass.

Current CI `.github/workflows/ci.yml` provisions PHP 8.3 and runs `scripts/test-php-laravel-adapter.mjs`, `scripts/test-php-laravel-scenario-bindings.mjs`, fake Mago integration, Composer-provisioned scenario E2E, migrations and parity. Its separate `mago-real` job verifies a pinned archive and runs `node scripts/test-mago-integration.mjs --real --require-available`. These jobs exist; this research did not run them or inspect a current CI result. They are not yet generated-DTO acceptance.

**Proposed #58 gate:** generate the entire acceptance corpus, PHP syntax-check and load it, run pinned Mago lint AND analyze over those exact files with explicit source roots and locked codec dependencies, assert no required errors/warnings and inspect expected file/rule coverage. Pair every rule with a deliberately violating case: missing strict declaration, mutable DTO, wrong promoted-property type, unsafe nullable access, unknown enum value, untyped collection, dynamic property, missing codec. Keep unsupported evidence visible; a fake analyzer, exit 0 or an empty receipt is insufficient. Format, if adopted, must run in check-only mode against a pinned configuration; no automatic fixes in the analysis gate.

Current documentation was fetched through Context7 `/carthage-software/mago`: [analyzer configuration](https://github.com/carthage-software/mago/blob/main/docs/content/en/tools/analyzer/configuration-reference.md) describes missing-type-hint, finality and array-index checks; [lint rules](https://github.com/carthage-software/mago/blob/main/docs/content/en/tools/linter/rules.md) documents strict-types. These establish available concepts, not compatibility of every current option with the repository's 1.0.0 pin. Probe the pinned executable/configuration and preserve its command/output fixtures before enabling any new option. Existing `tests/fixtures/mago/toolchain/mago.toml` and `scripts/test-mago-integration.mjs` are the starting point.

## 5. Wire contract and round-trip acceptance

Authorities: `docs/model.md`/`docs/ir.md` define field/type spelling; `docs/transport-http.md` and `contracts/transport-http.schema.v0.4.0.json` define HTTP names, body subsets, status and `lekalo-http-wire/v1`; `docs/error-contracts.md` defines semantic error identity/public payload; `docs/client-sdk.md` and `contracts/client-sdk.schema.v0.4.0.json` define the joined client projection. `adapters/node-typescript/src/client-sdk-gen.mjs::{camelIdent,requestBodyType}` distinguishes local parameter names from verbatim request-body field names. Reuse that #72 lesson and its actual joined projection, not an OpenAPI-only type reconstruction.

**Proposed rule:** wire names are verbatim. A PHP property may be deterministically camel-cased, but `task_id` must remain `task_id` in JSON. The camel-case default `operationId` is a method identity rule, not a recursive body renaming rule. Explicit transport query/header/cookie/path aliases override local property spelling only at those bindings; whole-input bodies preserve declared input names and explicit bodies preserve their declared subset. The codec mapping records each difference explicitly.

Round-trip has two separate assertions: decoding then encoding a valid wire value preserves canonical JSON semantics, including absent vs null, empty object vs list, enum values and lexical policies; encoding then decoding a valid DTO preserves its typed values/presence. JSON whitespace/object-key order may canonicalize; unknown members, duplicate keys, malformed values and precision loss must not silently disappear. Test direct canonical wire vectors as well: two mutually wrong codecs can round-trip while both violate the public contract.

**Proposed errors/results:** generate finite operation-specific success/error variants from the #62 binding, typed payloads from the registry and explicit accessors/factories. Do not create an unconstrained `Result<T,E>` runtime pseudo-type, catch-all error variant or generic Throwable as the domain union. Unit success is distinct from nullable output and HTTP 204. Serialize errors using the declared canonical envelope `{"ok":false,"error":{"id","code","category","payload"}}`, exact immutable ID/code/category, and public payload only. Undeclared infrastructure failures remain distinct. Do not impose an invented success envelope on transport contracts that declare a direct body.

## 6. Explicit unsupported emission

PHP has some native unions; the unsupported boundary is semantic representation, not a claim that PHP has no union syntax. **Proposed v1 support:** nullable types, typed list specializations and finite #62 operation results. Reject arbitrary structural/discriminated unions without a declared discriminator/codec, unbound type variables, higher-kinded generics, unsupported recursive codec cycles and collection shapes lacking a lossless wire policy. PHPDoc templates are analysis metadata, not enforced native generic types.

Map wrappers are currently source-invalid, before PHP mapping. **Proposed future map representation:** concrete immutable keyed collection with declared key/value codecs, JSON-object preservation and explicit handling of numeric-looking keys; require an owning Model/IR or attachment successor first. Do not infer a map from an associative array or turn `{}` into `[]`. Generic results outside #62 likewise require an owning contract. Unknown type tags must fail closed rather than fall through to `mixed`, `array`, `object` or string.

**Proposed diagnostics:** register a `php-types.mapping-unsupported` rule and bounded reasons such as `map-not-in-ir`, `generic-unbound`, `union-codec-missing`, `recursive-codec-unsupported`, `scalar-codec-unavailable`. Carry semantic ID/source pointer and capability reason, with deterministic ordering. Illegal source syntax remains a core validation error; well-formed but unsupported target projection becomes an explicit generation finding. Plan all reachable types before producing writes: one unsupported required type means no partial DTO publication, no success receipt and no fabricated full capability. Verify and portability reporting must retain that reason.

## 7. Stable ID linkage and provenance

Existing emitted scenario maps use `declarations[{id,start,end}]`; `orchestration/generate.rs::{source_map_binding_for,module_path_of}` ingests maps and probes PHP as an alternate artifact extension. `crates/lekalo-core/src/artifacts/source_map.rs::validate` checks input revision, actual byte bounds and lifecycle: non-generated artifacts cannot carry generated ranges. `contracts/trace-manifest.schema.v0.2.16.json` and `docs/trace-manifest.md` govern exported trace, not free-form comments.

**Proposed type output:** class declaration map ranges use the actual Lekalo symbol ID; emit an ID comment or typed attribute for readability, plus a validated sidecar for authoritative linkage. Field rows retain owning semantic ID, canonical pointer, field name and source span, separate from artifact byte offsets. A field name appended to a symbol is not automatically a valid semantic ID. Add enum-case/value and referenced-type links without inventing definitions.

**Proposed provenance:** exact adapter version/artifact digest, Model/IR revision, target-profile and codec policy digest, dependency lock digest, error/transport/query attachment digests where consumed, FQN/path, lifecycle and content digest. No timestamp or absolute path in generated bytes. Bind source spans separately to source bytes, since canonical IR deliberately excludes layout. Escaping must prevent descriptions/newlines/comment delimiters from injecting PHP; reuse the purpose of existing `php_comment_safe` and test hostile text.

Do not attach generated ranges to scaffolded/checked classes. Re-scan maintained source and publish observed locations with their current source fingerprint. **Proposed extension:** explicit PHP artifact path binding for type maps rather than relying solely on extension probing, validated for manifest membership and scope. Preserve maps for other targets during regeneration. Rewriting a namespace/file mapping changes artifact provenance, never semantic identity; approved rename history links old/new identities explicitly.
