# Issue #50: the daily-planning vertical slice — implementation notes and evidence

The research plan lives in
[issue-50-research.md](issue-50-research.md); this note records what
landed, the measured split between generated and maintained code, and
the evidence artifacts a future Node/Go target comparison reuses.
Public model, fixtures, and evidence name only `planner` — no
consumer-application name appears anywhere.

## What landed

- **Canonical module.** `planner.user_task_planning` with the
  per-workspace/user/task identity, `planned_for`, `position`,
  `focused_at`, `paused_at`, and the optimistic `reorder_version`,
  plus six commands (plan/move/unplan/reorder/focus/pause), three
  queries (today/backlog/carry-over), two deny policies, four planning
  events, and eleven endpoint bindings — all in the routes-corpus
  model (`tests/fixtures/php-laravel/routes/model/`), IR recompiled
  and committed.
- **OpenSpec requirement bindings.** `requirements.attachment.json`
  plus the `openspec/specs/planner/spec.md` provider tree bind nine
  symbols to six requirements with exact body revisions;
  `lekalo requirements validate` reports 6 requirements, 9 references,
  9 fresh, 0 stale, 0 conflicts, 0 coverage gaps, and the neutral
  requirements trace is committed as evidence.
- **Contracted operations and routes.** The composed
  types+operations+routes run generates the whole surface: the focus
  recipe stays the one `single-entity-update`; plan/move/unplan/
  reorder/pause delegate through five narrow command ports inside the
  required `TransactionPort` run; the three day lists are
  `port-delegation` queries over the declared collection classes,
  encoded at the boundary through their declared result codecs.
- **The embedded #62 registry grew additively:** `planning_conflict`
  (LEK-ERR-006), `planning_denied` (LEK-ERR-007),
  `planning_not_found` (LEK-ERR-008), `reorder_stale` (LEK-ERR-009),
  plus registry bindings for the eight new operations; existing ids
  are reused everywhere else.
- **Maintained Laravel boundary.** The fixture app gains the
  `user_task_plannings` migration (composite unique identity, the
  partial one-active-focus index on tasks), five command-store
  methods, three readers, five policy gates, the actor/workspace/
  clock middleware seam, and the manual provider webhook — all under
  `App\Lekalo`, all maintained code.
- **The nine scenarios run through the real HTTP kernel** in the
  routes harness's planning-battery stage: plan/move/unplan, two
  users planning one task, carry-over with byte invariance, the
  one-active-focus constraint proven through a second database
  connection, the stale reorder compare-and-swap, the midnight
  boundary splitting today/carry-over by actor zone, the repeated
  idempotency key (replay + same-key/different-body conflict), the
  unknown task and the declared infrastructure failure, and the
  provider webhook leaving every planning byte unchanged.

## Measured split (baseline vs Lekalo-assisted)

Measured on the landed branch:

- **Generated:** 113 files, ~255 KB — the typed PHP types, inputs,
  codecs, collections, DTOs, handlers, delegates, policies, ports,
  errors, thin controllers, request bindings, the envelope/error-map
  primitives, the verbatim `openapi.json`, the classmaps, and the
  custody sidecars — regenerated byte-stably from one validated join.
- **Maintained:** 21 PHP files, ~1100 lines in the fixture `app/` —
  the framework boundary (kernels, middleware, providers, models) and
  the port bodies that own the complex semantics (the planning store,
  the day queries with actor-local timezones, the policies, the
  transaction adapter).
- **Hand-written per governed operation:** exactly one maintained
  port body plus one container binding line; no handler, controller,
  request class, error class, or OpenAPI fragment was authored by
  hand. The #60 corpus carried 3 endpoints and 2 operations; this
  slice grew the governed surface to 11 endpoints and 10 operations
  with the fixture delta concentrated in the port bodies — the
  denominator a Node/Go comparison reuses.
