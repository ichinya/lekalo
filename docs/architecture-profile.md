# Architecture profiles

**Implemented (core milestone, issue #84):** versioned, opt-in architecture policy over declared Model/IR facts. Ordinary compilation and semantic validation remain mandatory. Selecting a profile changes severity and evidence obligations; it grants no source, execution or generation authority. The original observed/contracted modes and producer profiles keep their existing meanings.

The language-neutral catalog contains fifteen requirements with owner, producer, measurement, coverage, blocking basis, rationale and concrete alternative. Native typing, immutability, entrypoint uniqueness, observers, service locators, repeated generation, exact native bindings, errors as values and complete duplication tracking remain unsupported by this core surface. Scenario declarations and abstraction radius are partial signals. Their availability does not prove native execution or agent comprehension.

The closed contracts are `architecture-rule-catalog`, `architecture-profile`, `architecture-profile-resolved`, `architecture-profile-lock`, `architecture-profile-report`, `architecture-profile-diff` and `architecture-adoption`, version `0.6.5`, under `contracts/`. They pin the catalog bytes and independently admitted diagnostic registry successor `0.6.5` (508 entries); existing commands retain the `0.6.4` registry and their frozen contract pins. JSON input is bounded to 8 MiB and rejects duplicate keys and unknown members. Schema shape is only one admission layer; core also checks sorted unique rules, exact references, parent pins, scope grammar and policy invariants.

```sh
lekalo --json architecture-profile catalog
lekalo --json architecture-profile resolve --architecture-profile ai-strict
lekalo --json architecture-profile lock
lekalo --json --no-cache architecture-profile assess --all --architecture-profile ai-strict --check --project tests/fixtures/context-budget/planner
```

`catalog`, `resolve`, `lock`, `assess` and `diff` are read-only. Output goes to the ordinary CLI stream; callers explicitly persist it if needed. `--architecture-profiles FILE` selects an exact closed collection, without reusing other commands' `--profiles` or `--policy` documents. Profile version `1` is admitted; unsupported versions fail closed. `lock` emits a dedicated sidecar, separate from `lekalo.lock`. `assess --architecture-lock FILE` checks every resolved profile and assignment against the current document. `diff --base-profiles FILE --candidate-profiles FILE` reports enablement, severity, evidence, limits, membership, assignments and document provenance even when Model is identical.

The embedded inheritance chain is `legacy-observed` -> `contracted-standard` -> `ai-strict` -> `managed-generated`. Legacy keeps optional architecture measurements disabled. Standard collects available signals without requiring native evidence. AI strict requires complete declared identities, imports and semantic context estimates. Managed additionally requires deterministic generation evidence, so its current core check reports an evidence gap. An `enforced-core` assessment covers only its explicit selections, and is not certification of all fifteen rules.

Each parent reference binds ID, version and effective rule digest. One parent, at most eight levels, and a complete root inventory are required. Inherited disablement, severity reduction, evidence removal and limit relaxation are refused. Module assignments cannot weaken their selected project profile. Root policy changes are admitted as explicit documents and are visible in `diff`; v1 deliberately has no weakening acknowledgement escape. Default-error identities cannot be disabled, lowered or waived, and architecture selection cannot suppress ordinary semantic errors.

Scope assignments use exact `{kind:"project"|"module", id:SEMANTIC_ID}` values; there are no globs, path prefixes or recursive module selections. At most one assignment per scope is admitted. All assignments must identify current subjects, including assignments outside the selected module. An exact project assignment supplies the default selection; an explicit conflicting selection is refused. Each exact module assignment replaces that module's effective architecture selection, while dependencies remain in semantic/context closure. An explicit `--all` or `--module ID` selector is required. Without an assignment or explicit profile selection, assessment uses `legacy-observed`. Existing commands never infer architecture opt-in.

Fan-out and semantic-token limits have no universal default. A known limit requires an explicit `calibrationRef` and a nonnegative maximum; only the two complete measured catalog signals accept limits. Equality passes and one-over produces a witnessed violation. A calibration reference is a caller-supplied review identity, not verified empirical calibration. Partial, unknown and unsupported signals never become clean evidence or subjective style violations; an explicitly required missing signal is an `evidence-gap`. The report keeps raw values, witnesses, original coverage, severity, rationale and alternative, including adopted violations. Advisory runs return evidence with exit 0; `--check` returns `denied`/exit 3 for a violation or required evidence gap.

```sh
lekalo --json --no-cache architecture-profile assess --module planner --architecture-profiles profiles.json --architecture-profile ai-strict --baseline baseline-report.json --adoption adoption.json --as-of 2026-10-04 --check --project project
lekalo --json architecture-profile diff --base-profiles previous-profiles.json --candidate-profiles profiles.json
```

Baselines are full immutable report documents, admitted with recipe, scope, inventory, policy, coverage, selection and condition checks. An adoption ledger pins the exact baseline and current architecture snapshot. Each debt entry needs a matching complete measured baseline violation, exact condition digest, owner, reason, review reference and expiry. Active matching debt changes disposition to `adopted` without changing raw evidence. Changed or increased debt, expired debt and new violations still deny; semantic identity rules cannot be debt. `--as-of` is explicit and dates are calendar-validated. A baseline alone grants no exemption. Current mechanics adopt exact measured conditions; they do not implement generalized trend budgets or automatically replace baselines. Caller review establishes historical truth: a hash authenticates content, not its origin.

**Planned boundaries:** adapter-owned target catalogs and qualified native evidence admission, Laravel-to-Mago integration for architecture selections, upstream semantic-diff/lock envelope integration, richer adoption audit/trend budgets, and reproducible A/B outcomes. Core adds no PHP/Laravel/Mago recognizer and performs no native tool execution. Existing target adapter strict/Mago surfaces remain separate. AI task speed, comprehension, change safety, regressions and review quality require separately executed controlled experiments; structural metrics are not outcomes.

The live CI gate is `scripts/test-architecture-profile-contracts.mjs`, in the `build-test` lane after `cargo build --workspace --locked`. It requires exact Ajv `8.17.1`, all seven schemas and synthetic goldens, registry union preservation, fixture provenance and `scripts/gen-architecture-profile-contracts.mjs --check`, plus fresh binary results and negative probes.
