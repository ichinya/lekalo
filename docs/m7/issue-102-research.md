# Issue #102: privacy-safe public metrics export research

Research only, 2026-10-04. Acceptance authority: [live issue #102](https://github.com/ichinya/lekalo/issues/102), read through the authenticated GitHub Issues API, including its eight acceptance criteria. Branch: `ichinya/m7-issue-102`; inspected starting HEAD and local `ichinya/M7`: `a2aa1893766c01434842ca5062188a43898f41c5`. Product: `0.6.4` (`Cargo.toml`); diagnostic registry: `contracts/diagnostic-registry.v0.6.4.json`, 500 entries. Initial worktree and index were clean. Structure and evidence depth follow `docs/m7/issue-76-research.md` and `docs/m7/issue-77-research.md`; their implementation inventories were not assumed current.

**Decision (proposal):** add a separate `lekalo metrics export` orchestration surface that consumes only typed, versioned #121 records selected by an accepted #100 evaluation result. Build a new `aggregate.artifact`, apply the exact #120 derived-artifact decision contract and #119 redaction/leak primitives, then expose the exact candidate bytes before a digest-bound confirmation. Keep raw records and source membership local. Reuse #121 dependent invalidation for the aggregate and its export claim; couple publication eligibility to live source and authorization checks. Do not add an export verb to the recorder or treat generic `privacy export` as an aggregation engine.

**Sequencing constraint:** [#100](https://github.com/ichinya/lekalo/issues/100) is OPEN at the research date. It owns evaluation execution, approved A/B baselines, trial membership and evaluation-result semantics. #102 cannot publish a Framework Lift result before that handoff exists. [#119](https://github.com/ichinya/lekalo/issues/119), [#120](https://github.com/ichinya/lekalo/issues/120) and [#121](https://github.com/ichinya/lekalo/issues/121) are CLOSED; they supply enforcement, policy and records respectively, not completed #102 evaluation/export acceptance.

**Proposal marking convention:** every section titled “Proposed”, every table cell marked **Proposal**, and every explicitly proposed command, document or schema shape describes future work. All new paths, APIs, fields, diagnostic names, flags, recipes and gates in those scopes are proposals. `<V>` denotes the implementation's allocated contract version under `scripts/check-contract-versions.mjs`, not a version assigned here. This deliverable changes only this research file; it implements no command, schema, policy successor, fixture or gate.

## Proposed command/report schema

### Command choice and ownership

| Alternative | Decision and reason |
| --- | --- |
| Extend `lekalo privacy export` with history selectors and evaluation recipes | **Proposal: do not choose for v1.** Its positional artifact input, generic payload synthesis and consent slot lack experiment membership, minimum sample, source lifecycle and aggregation evidence. Adding these would make a generic enforcement entrypoint own evaluation semantics. |
| Add `lekalo history export` | **Proposal: reject.** #121 explicitly excludes public export and fixes records as private/ineligible. |
| Separate `lekalo metrics export`, reusing privacy and history services | **Proposal: preferred.** Metrics owns selection, aggregation, preview and lifecycle; history owns records/deletion; privacy owns decision vocabulary/redaction/scanning; #100 owns evaluation membership and assertions. |

Proposed grammar, all flags and paths below are future surfaces:

```text
lekalo metrics export --evaluation ID --scope TOKEN --recipe FILE
  --as-of DATE --dry-run [--authorization FILE] [--project DIR]
lekalo metrics export --evaluation ID --scope TOKEN --recipe FILE
  --as-of DATE --confirm PREVIEW_DIGEST --authorization FILE [--project DIR]
lekalo metrics export status EXPORT_DIGEST --scope TOKEN [--project DIR]
```

**Proposal:** `--dry-run` and `--confirm` are mutually exclusive; omitting both is a usage refusal. `ID` selects a local #100 result, not arbitrary raw JSON or a remote URL. `--scope` retains repository/tenant isolation. Recipe and evidence input use bounded confined reads. First invocation has no history registration, staged package or publication side effect; it can report a blocked candidate and the exact metadata subject needed to obtain authorization. A publishable preview requires verified current authorizations. The caller cancels by stopping after preview; a UI may label this action Cancel, without implementing a separate CLI cancellation database.

**Proposal:** core analysis in `crates/lekalo-core/src/metrics_export/{selection,aggregate,recipe,privacy,manifest,lifecycle,canonical}.rs`; thin CLI parses selectors and renders receipts. Add a bounded typed history snapshot service inside the #121 owner, not direct SQL in metrics code or parsing human CLI output. Add a typed #119 plan/enforcement seam able to accept the complete derived decision input and reevaluate the final candidate. It must retain exact evaluator/redaction ownership; `run_export` as currently implemented is not that seam.

**Proposal:** confirmation recomputes exactly the displayed selection and package, including source generation/digests, admitted aliases, recipe, as-of and authorization state. Require the reviewed preview digest, then recheck liveness and privacy immediately before marking an export releasable. A changed input, stale consent, deletion, residual leak or changed recipe requires a new preview. No command may upload merely because preview succeeded. Initial delivery can produce a local release package; any destination transport must consume that exact package and perform the same final eligibility check. Remote delivery receipts/acknowledged revocation are a separate capability, not provided by current `DestinationSpec::Publish`.

### Source admission and #100 handoff

**Proposal:** accept only `run-record@0.4.0` and its digest-bound assertion sets, or separately reviewed explicit successors. Observation documents are ingestion inputs, not durable export sources. Reject a schema-valid loose file masquerading as a live stored run. Require an accepted #100 result that identifies all planned trials, arm assignments, task/fixture/revision matching, complete/excluded/infrastructure dispositions, hard-assertion selection, exact model/provider/harness/runtime pins and baseline approval. Resolve that selection against live same-scope #121 rows and use stored measurement sources. Exclusions must be predeclared and reported; outcome-based selection is invalid.

**Proposal prerequisite:** current authority lacks recorder kinds, and derived-source validation requires every source kind/default disposition and exact policy/classification ref to be accepted. A #120/authority successor must admit recorder kinds and compatible history provenance, or #100 must produce an explicitly admitted local measurement projection with verified links to the original runs. The latter still needs approved ownership and cannot claim HLV ownership merely by choosing `metrics.evaluation-evidence`. Specify the chosen migration/projection in #100/#120 handoff; preserve original refs and record an explicit conversion decision. Mixed old/current refs fail closed until that reviewed path exists. #102 must not invent a local taxonomy or label its raw sources public.

Current record gaps relevant to #100 are concrete: there is no experiment/arm/task-trial membership, provider identity, cached-token leaf, first-pass/verified-task-success metric, fix-cycle leaf, human-intervention count, unrelated LOC count or pricing-snapshot ref in `run-record@0.4.0`. Harness `modelId/modelRevision` and retry/replan fields do not prove these other meanings. Keep missing leaves unknown or unsupported according to actual producer capability; do not hide new members in tokens, source ids, diagnostics, test ids or assertion prose. #100 owns a reviewed result contract and any necessary recorder successor.

### Public payload, local custody and manifest

**Proposal:** introduce closed Draft 2020-12 `contracts/public-metrics.schema.v<V>.json`, `public-metrics-manifest.schema.v<V>.json`, `metrics-aggregation-definition.schema.v<V>.json` and `metrics-export-preview.schema.v<V>.json`. Payload/manifest together are an `aggregate.artifact` package; full source provenance and decision evidence stay an `aggregate.decision`. Reuse admitted homes `.lekalo/privacy/aggregates/<package-id>/` and `.lekalo/privacy/decisions/aggregate/<local-id>.json`, subject to physical confinement and local ignore protections. No new authority kind or public home is assumed approved merely by proposing these files.

**Proposal:** local decision ledger retains the complete selected source ids/digests, assertion references, source-policy provenance, experiment/arm membership, exact input/review fingerprints, generation, authorizing evidence and subject digest. It is private even if every measured outcome is harmless. Public reproducibility means a recipe, safe sufficient statistics and exact allowed provenance; full source recomputation remains a local custody operation. Avoid a public hash of the source set, repository identity, tenant token or small-domain values: it is a linking/dictionary oracle, not anonymization.

**Proposal digest format:** use `sha256:<64-lowercase-hex>` consistently. Canonical payload bytes: compact UTF-8 JSON, recursively byte-sorted object keys, declared set-array ordering, no BOM, one LF; exact decimal/rational numeric rules below. Manifest contains `payloadDigest`, not its own digest. Define `packageDigest = SHA256(canonical({payloadDigest, manifestDigest, reportDigests}))`, where each leaf digest covers separate exact bytes and the sorted report list is versioned. A small local receipt carries `packageDigest`; avoid self-referential file hashes. The confirmation `previewDigest` additionally binds local selection/generation, as-of, authorizations and final public byte digests; it never leaves the local review flow. Byte-digest integrity does not authenticate a publisher.

## Proposed aggregate definitions with data sources

Define each field's exact source pointer, unit, population, independent sampling unit, grouping keys, transform, missing-state rules, sufficient statistics, rounding and comparison orientation. The machine version/digest controls execution; explanatory prose cannot override it. No implicit current pricing, provider lookup or ambient filesystem scan enters aggregation.

Totals/means use known values; pooled coverage is `sum(includedFacts)/sum(candidateFacts)` over trials with both known and valid, not average of ratios. Zero candidate denominator yields unknown. Explicit reported ratio is a different leaf with its own sample coverage. |
| Retries/replans/fix cycles | `metrics.retryCount`, `replanCount`; no fix-cycle leaf. | Sum/mean retries and replans separately. They are not interchangeable with fixes; fix cycles remain unknown pending a #100-defined producer/record successor. Do not fabricate fix count as retry + replan. |
| Confidence/sample metadata | Record/repeat coverage and known-state wrappers; no general statistical confidence object. | Report distinct scheduled trial count, known/unknown/withheld/unsupported leaf counts, repeated-input/cluster basis and recipe-defined uncertainty. Confidence methods come from #100; unexecuted statistical analysis remains unknown, not a high-confidence claim inferred from a green gate. |
| A/B deltas and negative/neutral results | #100 result membership, immutable baseline and approved paired task/revision pins are outstanding. | Require compatible arm/group recipes. Compute `B-A`, success-rate lift in signed percentage points, and explicit relative deltas only for a known nonzero baseline. Equality is known zero; negative lift or increased cost remains signed and visible. Invalid pairing produces unknown comparison, not exclusion of an inconvenient run. |

**Proposal arithmetic:** compute integers with checked wide arithmetic; public JSON numeric integers stay within `2^53-1`, otherwise reject or use a declared decimal-string statistic, never round silently. Cost uses exact scaled decimal integers; ratios/means use normalized `{numerator,denominator}` decimal strings with denominator positive. Any rendered decimal fixes precision and ties-to-even rounding in the recipe; it does not replace the exact rational. Variance uses known count/sum/sum-of-squares with the declared sample estimator; clustered/repeated tasks do not become independent merely because run ids differ.

### Four-state uncertainty and minimum sample

**Proposal:** reuse exactly `known|unknown|withheld|unsupported`, with only `known` carrying `value`. A privacy/sample restriction dominates publication of a value and yields withheld; the private ledger retains the original missing-state distribution. Without a restriction, all-producer-unsupported yields unsupported, absent or insufficiently observed evidence yields unknown, and a permitted statistic over enough known independent samples yields known. A metric observed as zero is known zero. Publish a partial known-sample mean only when the recipe explicitly permits it and its coverage counts are safe; complete-population totals and cost-per-success stay unknown when required inputs are missing.

**Proposal initial disclosure floor:** use `k=5` as a conservative engineering default per released cohort and per statistic's known independent trial population, including comparison arms. Count predeclared #100 trial units, not retries, assertion rows, duplicate ingestion or repeated export attempts. This number is a proposal, not a shipped #120 value or a formal anonymity guarantee; admission requires review and recipe versioning. #100's “three tasks” acceptance criterion does not itself meet a per-cohort sample rule. A small completed evaluation can remain a valid local result while public metrics are withheld.

**Proposal:** exact sample size, each outcome bucket, missing-state counts, quantiles, small strata and denominators obey the same disclosure rule. When a small bucket could be recovered by subtracting others from the total, suppress the distribution and enough companion totals as a unit; never publish a single withheld bucket with all complementary counts. Maintain a private release ledger to detect overlapping/near-complement selections and repeated snapshot differencing. V1 may refuse an overlapping release and require a reviewed replacement/invalidation rather than claiming minimum sample alone prevents inference. Even with k, exact high-dimensional metadata can identify a consumer; coarsen to approved catalog dimensions or withhold the cohort. Differential privacy and unrestricted query APIs are separate work.

### Role-alias registry and forbidden categories

**Proposal:** version a public alias registry (`contracts/metrics-role-aliases.v<V>.json`) that maps a role and export-scoped cohort alias to approved presentation metadata. Reuse #120's exact roles (`consumer-repository`, `lekalo-repository`, etc.) as the normative role vocabulary; `consumer-01` is a presentation alias, not a new policy role. Local mappings reference generated repository tokens, not hashes of URLs, names or host paths. Mapping assignment is pinned before aggregation; do not derive alias order from repository names. Reuse an approved mapping within a comparison, and avoid cross-export consumer linkability by default. The public registry contains no reverse mapping or private identifiers.

| Category forbidden by default | Proposed positive projection and enforcement |
| --- | --- |
| Source snippets and source maps | Never load source/observed inventories. Closed output allows metric leaves only; no string payload, sourceRef, span or map member. |
| Prompts, responses and tool arguments | No transcript input or passthrough bag; token/tool-call counts are typed numbers, not transcript excerpts. |
| Absolute paths and repository URLs | No path field is needed publicly. Role aliases replace repository identity. Reject rather than normalize an attacker-controlled unknown metadata field into the public schema. |
| Secrets, PII and tenant identifiers | Drop repository/tenant/run tokens and source digests at projection; scan all candidate files and failure/report channels with #119 primitives. Private authorizers' identities stay local. |
| Private-consumer native symbol names | Exclude affected semantic ids, assertion/test ids, diagnostics details and arbitrary profile/harness labels. Admit catalog metadata explicitly; ordinary token-shaped private names can evade the eight-class scanner. |
| Raw test/tool output | Use closed status/count summaries and stable registered codes only where the recipe admits them; never emit raw stdout/stderr, assertion expected/actual values or failure prose. |

**Proposal:** redaction diff records dropped/transformed field categories, safe aliases and occurrence counts, not original values or snippets. Preserve measurement failure/unsupported verdicts across transformation. A leak in a numeric metrics package is a projection/admission defect: refuse publication rather than silently change a number to a marker or turn the whole result into a content stub. Rescan payload, manifest and every included report after final serialization; an empty residual list is necessary but only proves the scanner's declared vocabulary.

## Proposed determinism strategy

**Proposal:** pin #100 result/protocol and baseline, exact run/assertion bytes and policy compatibility path, immutable recipe/alias registry, core/adapter/profile/harness versions, all source-field measurement conventions, approved evidence, and an explicit evaluation as-of. Hash final bytes with the declared canonical writer. No current provider price, current Git checkout, current scan, random alias or ambient clock participates in the aggregate.

**Proposal:** take a bounded consistent history snapshot and visit source identities in canonical byte order locally. Deduplicate only identical same-scope run ids/body digests for ingestion; distinct scheduled trials remain distinct even with identical metric values. Reject duplicate conflicting identities, inconsistent assertion links, unknown source versions, mixed scopes and mismatched A/B inputs. Sort public cohorts by recipe keys and metric/statistic keys; set-like members have declared order, semantic ordered arrays retain order. Permuted record enumeration, list page sizes and SQL row order cannot change values or public digests.

**Proposal v1 bounds:** at most 1,024 selected source runs per package in one scope, fitting the existing dependent schema's source-run bound; at most 64 public cohort rows, 32 admitted metric ids per cohort and 1 MiB total public package bytes. Fail on an over-bound experiment rather than truncate its trials or silently export a favorable subset. Checked accumulators and bounded decimal precision apply before serialization. Larger complete evaluations need a separately versioned partition/combination recipe with disclosure checks, not an undocumented escape from the store/manifest bounds.

**Proposal:** selection uses all #100 planned trials with fixed eligibility rules, not a moving “latest successful runs” query. A new record or deletion changes source selection/eligibility and requires a new preview; do not silently update an approved package. Source ingestion timestamps/run tokens remain local; equivalent metric projections may share a public payload digest while having different private custody and preview digests. Distinguish these identities in tests.

## Proposed invalidation and publication lifecycle

The shipped #121 transaction removes records/assertions/index rows, transitively invalidates `index|claim|aggregate-input` dependents, erases their source lists and bumps store generation. Existing privacy evidence rejects `stale/expired` and mismatched subjects; it has no source-deletion callback. Authority provides ownership/path admission, not consent issuance. #102 needs a bridge between these mechanisms and the export manifest.

**Proposal dependent graph:** directly register an `aggregate-input` with every selected run; link an export-manifest `claim` to that dependent, and a publication `claim` to the manifest claim. Keep all direct source digests/assertion links in a local decision ledger. `register_dependent` already binds live sources and prevents cycles; no new store-dependent kind is necessary. A nested dependent resolution does not automatically supply a rehashed transitive record snapshot, so the new owner must traverse and validate the complete selected source set through #121 custody APIs.

**Proposal eligibility state:** preview is transient; confirmation creates a locally prepared package whose manifest is only releasable while sources/evidence resolve. Publication records `valid-at-export`; deletion/retention, lost assertion evidence, source corruption, revoked/expired authorization or incompatible policy changes make current status invalidated/unverifiable and block new delivery. Revocation never edits a prior signed/digested payload into a different metric result. Reaggregation uses a new recipe/selection/package identity and must satisfy the sample rule again.

**Proposal atomicity:** bind source liveness, generation and dependent registration under the history owner's transaction, write immutable staged bytes in an admitted confined home, then activate a small local package pointer only after a final source/authorization check. Missing pointers, incomplete staging and interrupted activation fail closed; recovery never exposes an unactivated package as valid. The filesystem and SQLite are not automatically one transaction. Use a bounded two-phase local protocol with recovery/journal states, then prove delete-between-preview-and-confirm, delete-between-staging-and-activation, crash and concurrent retention races. Do not claim that copying #119's two sequential writes solves this.

**Proposal:** deletion's committed invalidation is authoritative even if cleanup of a local exported file fails. `status` and any transport resolve the dependent graph and rehash live records before treating the immutable package as currently eligible. A lifecycle reconciler can remove inactive local package bytes and produce a safe tombstone; it must not retain erased source lists just to explain the tombstone. Public invalidation references only the export-scoped package/validation identity and fixed reason category. Keep protected detail local, and ensure revocation metadata itself passes disclosure policy.

**Proposal authorization invalidation:** resolve aggregation/declassification/transfer evidence with the exact subject/profile/policy and live evidence custody at confirmation and delivery. Do not manufacture `verified/current` in metrics code. Use explicit `as-of` for deterministic historical calculations and trusted current freshness for live eligibility; a caller's old date cannot prolong consent. Current #121 stores measurements/assertions/dependents, not a general authenticated consent issuer or revocation store. An evidence resolver and expiry/revocation protocol remain a prerequisite; classification `grant_is_valid` is a validity predicate precedent, not that resolver. Accepted privacy policy has no broadening grants, so user flags cannot override a refusal or the admitted sample recipe.

**Proposal external limitation:** no local delete can erase bytes already downloaded by another party. AC6 means dependent aggregate/export manifests become invalid and future claims/imports/delivery must consult a revocation/status channel; it does not mean recalling every copy. Future AIFHub imports should store package id plus validity protocol, honor tombstones and show unavailable validation as unverified. An offline import can validate bytes and historical `valid-at-export`, but cannot attest continuing source liveness. Specify this distinction in the public manifest and implementation acceptance.

## Proposed diagnostics families and codes

**Proposal:** add a bounded `metrics-export.*` / `LEK-METRICS-EXPORT-NNN` family through the registry owner when implementing; no registry entries are allocated here. Reuse existing `history.*`, `privacy.*`, `evidence.*`, `derived.*` and `leak.*` reasons without translating denial into success.

| Proposed diagnostic | Trigger / honest disposition |
| --- | --- |
| `metrics-export.evaluation-required` | Missing/unaccepted #100 result, unmatched baseline/arms or undeclared selection; block export. |
| `metrics-export.source-incompatible` | Wrong recorder version/kind/policy, unsupported admission migration, mixed scope or conflicting digest; fail closed. |
| `metrics-export.metric-unavailable` | Required producer/measurement missing; typed unknown/unsupported, with no fabricated numeric default. |
| `metrics-export.sample-withheld` | Disclosure population below k or unsafe companion counts; withheld projection remains explicit. |
| `metrics-export.overlap-refused` | Repeated/complementary release can reconstruct protected values; refuse until reviewed safe release recipe. |
| `metrics-export.metadata-not-admitted` | Arbitrary private profile/model/native identifier reaches a catalog field; withhold or refuse under the recipe. |
| `metrics-export.preview-stale` | Confirmed digest disagrees with recomputed sources/evidence/bytes; require a new preview. |
| `metrics-export.source-invalidated` | Source deletion, retention, invalidated dependent, corrupted body or lost assertions; block claim/delivery. |
| `metrics-export.authorization-unavailable` | Missing issuance custody, stale/expired/revoked evidence or inaccessible current validity; deny release, preserve fixed underlying reason. |
| `metrics-export.integrity-failed` | Payload/manifest/report digest, canonicalization or staging recovery mismatch; no partial package becomes active. |

**Proposal:** result envelope separates ingestion/evaluation verdict, disclosure state and export lifecycle. A package may export successfully while reporting worse outcomes for the Lekalo arm. A withheld metric is not a failed evaluation; authorization denial is not a measured task failure. Exits can reuse valid 0, invalid 1, denied 3, unavailable 4 and unsupported-version 5, but #102's closed receipt schema must specify preview-blocked/sample-withheld behavior explicitly. Emit fixed-token errors and safe aliases, never rejected identifiers or file contents.

## Proposed profile format

**Proposal:** an illustrative machine recipe fragment, not a valid committed fixture:

```yaml
identity: dev.lekalo.metrics-aggregation-definition@<V>
sourceFamily: dev.lekalo.run-record@0.4.0
evaluationProtocolRef: <exact accepted #100 ref>
policyRef: <exact accepted compatible #120 ref>
samplingUnit: scheduled-trial
minimumIndependentSamples: 5
groupBy: [repository-role-alias, pilot-mode, scope-state, stack-profile, model-harness, arm]

unknownPolicy: preserve-four-states

costGroupBy: [currency, basis, pricing-provenance]
comparison: candidate-minus-baseline
```

**Proposal:** no inheritance or arbitrary expressions in v1. Fixed ids select the recipe's allowlisted fields/statistics; unknown grouping dimensions, extra members, contradictory recipes, weakened minimum sample, dynamic source queries and price lookups refuse. Overrides may narrow a selected field set only if the resulting release is separately previewed and passes overlap/suppression checks. Pin approved experiment/recipe versions so an operator cannot hide an outcome by changing grouping, denominators or exclusion rules after seeing results.
