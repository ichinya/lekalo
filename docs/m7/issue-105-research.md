### Authority and ownership modes

The entry authority matrix must preserve the accepted separation: OpenSpec owns requirements/change intent; AI Factory owns execution plans/state and its normalized QA custody; Lekalo owns semantic Model and derived semantic/runtime homes; HLV owns its validation/traceability results; source/native toolchains own source code and native tests/evidence. Neither a graph, provider manifest nor workspace note replaces these inputs. Generated code acquires only the lifecycle/write authority explicitly admitted by the artifact plan.

| Adoption mode | Meaning and transition evidence | Generation authority |
| --- | --- | --- |
| Observed | Read/index existing code into derived observations. Origin, confidence, incomplete scope and fresh/stale/unknown states remain visible. Confirmation records mapping decisions; explicit promotion creates canonical Model definitions. | No implementation rewrite from scanning or adoption. Inferred observations are not canonical declarations. |
| Contracted | Canonical semantics bind to maintained implementation/native tests through a checked declaration. Drift/conformance checks report limitations and stale evidence. | Maintained bodies remain source-owned; a contract or confirmed binding does not authorize replacement. |
| Managed | Explicit generator/target capabilities and ownership plans govern selected generated artifacts; verify/check detect drift and missing capabilities. | Only declared eligible writes under a reviewed plan, not the entire repository. Scaffolded/checked/custom/external files retain their distinct regeneration rules. |

These are responsibility modes, not authority lifecycle classes (`canonical`, `derived`, `cached`, `runtime-only`, `direct-evidence`) or artifact lifecycles (`generated`, `scaffolded`, `checked`, `external`, `custom`). Current Model has no blanket module-mode field. Present transitions per symbol/artifact and mixed ownership within a repository; do not add undocumented `mode: managed` YAML.
