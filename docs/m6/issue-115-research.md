## Hono documentation evidence and supported boundary

Context7 resolved Hono and queried official documentation using `/websites/hono_dev` on 2026-09-30. These are current API descriptions, not an installed or tested Hono pin. S1 must select exact locked Hono and optional integration versions and capture executable reference behavior before claiming compatibility.

- [Routing](https://hono.dev/docs/api/routing): verb methods, `all`, `on` with method/path arrays, nested `route`, and `basePath`. Preserve declared wildcards/parameters; don't turn patterns into enumerated concrete endpoints.
- [Middleware](https://hono.dev/docs/guides/middleware): registration order controls entry; post-`next()` work unwinds in reverse. The chain records possible applicability/order, not proof that every middleware reaches `next()` or that authorization is correct.
- [Hono API](https://hono.dev/docs/api/hono): `strict` distinguishes trailing-slash behavior. Routing also supports custom `getPath`; a scanner must record an unsupported/unknown path interpretation instead of pretending these are normal URL paths.
- [Validation](https://hono.dev/docs/guides/validation) and [Zod OpenAPI example](https://hono.dev/examples/zod-openapi): validators precede handlers, `req.valid` consumes a validation target, and `OpenAPIHono.openapi(route, handler)` supplies request/response metadata. Detect schema references without executing Zod/schema factories or deriving canonical domain constraints from TypeScript types alone.
- [JSX](https://hono.dev/docs/guides/jsx) and [basic routes](https://hono.dev/docs/getting-started/basic): `c.html(JSX)` and renderer-backed `c.render` are positive SSR evidence. A `.tsx` extension alone is insufficient; `c.html` with a plain string establishes HTML, not necessarily JSX/SSR. Mixed/unknown return paths remain explicit.
- [Testing](https://hono.dev/docs/helpers/testing): `testClient(app)` can bind a request to a concrete app. S6 additionally qualifies `app.request` and direct imported-handler tests against the selected pin. Tests run only on trusted synthetic fixtures in an independent test harness, never during scan.

Initial supported syntax: compiler-resolved Hono/OpenAPIHono constructors and import aliases/reexports; immutable aliases; top-level straight-line registrations; bounded pure local registration functions with known arguments; literal methods/paths and immutable literal constants/arrays; named/imported/property and inline handlers. Resolve composition across imported modules with proven initialization order. Calls behind environment conditions, mutable aliases, arbitrary factories, loops with nonliteral inputs, getters, computed callees, custom routers/path transforms and `mount` of an arbitrary fetch app retain candidate spans plus incomplete/unknown reasons. No application evaluation or guessed values.

## Evidence, confidence and contracts

Use a neutral full-evidence envelope transported on scan, then validated/persisted by core. Recommended **new** `contracts/framework-evidence.schema.v0.4.0.json` describes generic records; **new** `adapters/node-typescript/contracts/hono-evidence.schema.v0.4.0.json` describes Hono payload/recognition vocabulary. Core must not import the Hono schema or switch on its methods. The adapter validates Hono payloads and projects generic nodes, relations, ordered groups and facets; a trusted versioned extension descriptor registers their namespace and allowed identities.

| Required fact | Concrete representation / validation |
| --- | --- |
| Semantic/native symbol | `from`/`to` native IDs with independently optional semantic binding refs and candidate sets. Unbound routes/services remain native facts; no synthetic canonical command/query/entity is created. Inline callbacks get a domain-separated native key tied to owner/registration occurrence and source fingerprint. |
| Relation kind | Adapter namespace `dev.lekalo.hono/` with closed entries such as route-handler, mounts-router, uses-middleware, validates-request, returns-response, handles-error, context-write, context-read, openapi-operation, handler-call, route-test. Namespace registration never overrides core relations. |
| Source span | Project-relative original-case path, half-open UTF-8 byte offsets, 1-based lines/columns; conversion from TS UTF-16 offsets against exact source bytes. Include source site and target declaration spans separately; test BOM, CRLF, multibyte and EOF. No raw snippet/absolute path in wire or queries. |
| Source revision | Content-addressed input manifest plus declared originating revision. Scan request ID/revision is an exchange identity, not a source revision. Dirty/uncommitted inputs are bound by bytes; never label them clean HEAD. |
| Provenance | Record fact origin explicit/detected/inferred plus confirmation state and optional exact confirmation receipt. Issue vocabulary `confirmed` is a displayed status, not evidence that a scanner can mint. Existing origin mapping: explicit → declared, detected → observed, inferred → inferred; reuse explicit/confirmed/inferred binding status without changing its meaning. |
| Confidence | Keep exact/high/medium/low/unknown, never percentages. Exact = resolved constructor/call symbol + static arguments + supported sequence, high = qualified deterministic adapter rule, medium/low = bounded candidate inference, unknown = absent/ambiguous dependency. Graph maps directly extracted facts to extracted and inferences to inferred/unknown; user confirmation of a mapping does not establish runtime verified authorization. |
| Adapter/framework version | Exact adapter id/version/artifact digest, TypeScript 5.9.3 pin/compiler digest, Hono and optional package versions/type/runtime digests, provider rule revision. A semver dependency range is not an exact framework version; absent package evidence means unknown and reduced completeness. |
| Freshness fingerprint | Domain-separated digest of relation, registration signature/order/mount path, involved handler/middleware/schema/test bytes, manifests/lock, tsconfig/resolution, provider policy and bound Model/IR/transport/binding digests. Store a dependency set for recheck, not only handler signature. |

Envelope also carries schema identity, producer custody, input digests, per-provider enabled/absent/disabled/unsupported/partial/complete state, per-group completeness, class/provenance and exact authorityRef/policyRef. Completion of the scan process is distinct from completeness of discovered routes. An unknown target stays an unresolved record with reason/candidates; overflow is a bounded explicit failure/partial result, never silently dropped edges.

Select versions from the authorized consumer's actual lockfile and a reviewed public fixture pin, not latest documentation. Do not add a runtime Hono dependency to the production scanner.
2. Add **new** fixture family `tests/fixtures/hono-bindings/` with `README.md`, locked runtime package metadata, `static`, `composition`, `middleware`, `http`, `openapi`, `ssr`, `tests`, `uncertainty`, `disabled` and `expected/` cases. Register synthetic application origin in `tests/fixtures/fixture-provenance.json`; separately record upstream type/runtime license/provenance in fixture README and `adapters/node-typescript/THIRD_PARTY_NOTICES.md` if bundled.
3. Qualify real Hono behavior in a separate synthetic runtime oracle: mount before/after child registrations, basePath views/shared routers, strict slashes, route callback arrays, matching middleware filters/order, onError precedence and JSX renderer. ### S3 — Symbol-resolved routes and deterministic composition

1. Implement **new** `node/hono-scanner.mjs` and `hono-routes.mjs`; inject `ts/checker/program/context/native-symbol lookup` from the same restricted scan. Constructor identity resolves to a qualified Hono package declaration; name resemblance is insufficient. Use checker aliases/resolved signatures and AST kinds, never regex-only claims.
2. Record registration events with app identity/view, source occurrence, method set, path expression, ordered callbacks and initialization dependencies. Support standard verb methods, literal `on` arrays and `all`; keep custom methods/ANY visible, but mark unsupported canonical HTTP joins instead of expanding them silently to guessed endpoints.
3. Resolve constant paths without evaluation: literals, immutable const aliases and bounded concatenation/template/array expressions whose leaves are all known. Enforce depth/record budgets and reject unknown expressions. Preserve parameter/wildcard semantics and slash/strict configuration; canonical endpoint path compatibility must be checked, not normalized by blind string replacement.
4. Process route/basePath composition in proven execution order. Bind mount occurrences separately, including shared child routers, and qualify whether child registrations are captured at mount time against S1 oracle. Detect recursive composition and unresolved cross-module order; retain partial subgraph and uncertainty rather than topologically inventing JavaScript execution.
5. Resolve every callback to a stable native symbol; inline callback keys include owner and registration position, with source/route fingerprint for changes. Multiple route callbacks remain a chain, not one arbitrarily selected handler. Reused/duplicate registrations keep distinct source occurrences and precedence.
6. Extend `scanner.mjs::indexReferences` with caller/callee native identities for exported, local and class-member calls; fix property name access and alias handling without weakening existing generic fixtures. Dynamic dispatch remains a candidate reference.
7. Gates: `hono-scanner.test.mjs`, composition fixtures, existing scanner tests and cold/repeat parity. Compare two independent scans and reordered file enumeration; compare stored expected bytes against each run directly, not against a session value overwritten by the second scan.

4. Recheck all dependencies before using or confirming evidence. Missing/deleted/out-of-scope input becomes unknown/stale. Stable-key relocation may preserve mapping with move history, but requires refreshed evidence spans/fingerprints.
5. Implement generic graph overlay materialization and indexes; load it in inspect/impact/context CLI composition. Reverse dependencies traverse middleware/schema/service/test edges; policies are not inferred as verified. Context budget exclusion must identify incomplete/omitted chain rows instead of presenting a shortened chain as complete.

Add **new** `crates/lekalo-core/tests/hono_bindings.rs` and **new** `crates/lekalo-cli/tests/hono_bindings.rs`: production bundle via confined TargetClient → typed scan → persisted observed bindings → actual inspect/impact/context JSON.
