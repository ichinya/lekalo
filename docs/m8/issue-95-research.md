# Issue #95: incremental watch feedback loop research

Research only, 2026-10-06. Acceptance authority: [live issue #95](https://github.com/ichinya/lekalo/issues/95), read with `gh issue view 95 --repo ichinya/lekalo --json title,body,labels`. Checkout: `ichinya/m8-issue-95`, inspected HEAD `15bd13917654dc20ad19b089a5bb8e5e29c2099f`, based on main; `Cargo.toml` and `docs/versioning.md` still name product `0.6.5`. The dispatched implementation target is M8 product `0.8.0`; the separate M8 branch's version bump is not present here. This research changes no product or contract bytes. All seven acceptance criteria, eleven capabilities, and nine requirements from the issue are mapped below.

Decision: propose a read-only `lekalo watch` command with a thin filesystem/process host and a pure core scheduler over immutable input snapshots. Keep one active run and one coalesced pending change set; reuse accepted loader, impact, artifact checks, and adapter contracts through snapshot-aware services. Publish complete diagnostic replacements for settled revisions and explicit terminal events for cancelled runs. Selective work must be measured, not inferred from module-filtered output.

All new paths, APIs, flags, codes, limits, schemas, and example event members below are **proposals**, not implemented features or reserved allocations. New/changed contracts take `0.8.0` in the implementation commit; unchanged families retain their exact accepted versions. The document follows the evidence inventory, proposal, determinism, diagnostics, test mapping, and risks shape of `docs/m7/issue-75-research.md`, `issue-77-research.md`, and `issue-103-research.md`.

## Proposed command/report schema

### Commands, flags, and ownership

The issue's commands are preserved exactly:

```text
lekalo watch
lekalo watch --validate --impact --generate-check
lekalo watch --module planner --json-lines
```

Additional proposed exact surface:

```text
lekalo watch --project . --validate --impact --generate-check --locked --target node-typescript --json-lines
lekalo watch --module planner --strict --debounce-ms 150 --max-wait-ms 1000
lekalo watch --backend poll --poll-interval-ms 1000 --reconcile-ms 5000 --adapter-timeout-ms 30000
lekalo --no-cache watch --validate --impact --json-lines
lekalo watch --help
```

| Option | Proposed behavior |
| --- | --- |
| `--validate`, `--impact`, `--generate-check` | Independent selected stages. With no stage flags, default to core validation; specifying any stage runs exactly that selection plus its mandatory preparation. No implicit adapter stage for bare watch. |
| `--module ID` | Select watch work for this module and its dependency/public obligation closure; still subscribe to project manifests, imports, profiles and dependencies that can affect it. Unknown IDs fail before watching. This is not a filesystem path. |
| `--target ID` | Repeatable selection of locked targets for ephemeral scan/validation within `--validate`. Missing, stale or unsupported selective capability produces explicit coverage/fallback; never infer installed adapters from arbitrary executables. |
| `--project DIR`, `--locked`, `--strict` | Reuse existing selector and policy meaning. `--locked` strengthens lock preflight; watch never updates lock. Strict policy retains unavailable required obligations as failures. |
| `--json-lines` | Closed newline-delimited stream on stdout, one compact UTF-8 JSON object per line, flush complete lines. Human projection otherwise. Reject global `--json` together with stream mode before work; global `--json` alone is rejected with guidance to use `--json-lines`. |
| `--debounce-ms N`, `--max-wait-ms N` | Defaults 150/1000; quiet interval coalesces events, maximum wait prevents indefinite starvation. Bounds 1–10,000/1–60,000 ms; max wait must be >= debounce. |
| `--backend auto\|native\|poll` | Default auto: recommended native backend; unavailable native backend can fall back to polling with a visible session event. Native never silently changes backend. Poll compares content hashes, not only timestamps. |
| `--poll-interval-ms N`, `--reconcile-ms N` | Defaults 1000/5000; bounded 100–60,000 ms. Reconciliation independently inventories classified inputs to recover missed native events. Invalid combinations are usage errors. |
| `--adapter-timeout-ms N` | Default 30,000; bound 100–120,000 ms. Applies to read-only adapter requests, preserves transport output caps. |
| Global `--no-cache` | Bypass fragment reuse for oracle/debugging; does not disable watch, snapshot capture, coalescing, or policy. |

No `--execute`, `--auto-generate`, script hook, production command, clean, install, format, or lock-update option is delivered in #95. Explicit opt-in auto-generation is a later issue and capability. All flags above need both root help and subcommand help tests.

New proposed owners: `crates/lekalo-cli/src/watch.rs` for backend subscription, signal handling and stream output; `crates/lekalo-core/src/watch/{mod,request,snapshot,changes,scheduler,selection,diagnostics,events,version}.rs` for typed state, planning and events. Expose proposed `WatchRequest`, `InputSnapshot`, `ChangeBatch`, `RunPlan`, `WatchSession::accept`, and `WatchSession::complete`. Filesystem acquisition stays behind the existing governed read seam; core decisions consume captured facts, never arbitrary callback paths. Extend existing loader/cache/validator/graph/artifact/orchestration seams instead of cloning their algorithms.

Default read-only means no changes to Model, target source, artifacts, manifests, lock, observed index, history, or durable cache. Keep fragment and capsule caches in session memory, using accepted content/version keys; do not call `Session::open` to create SQLite storage. If a future persistent-cache mode is accepted, expose its writes separately. Adapter launches, when targets are explicitly selected, use an ephemeral snapshot view and accepted confinement; backend unavailability must be reported rather than running with unproven read-only permissions. Temporary captured input material may exist outside the project and must be bounded and cleaned; it is not project regeneration.

## Snapshot and incremental semantics with data sources

1. **Subscribe before baseline capture.** Resolve the governed root, select input classes, attach directory watches, then capture initial inventory. Buffer events during capture and reconcile again so an edit between subscription and first run is not missed. Initial run is complete for the selected scope.
2. **Capture and revalidate.** Inventory project/module documents, imports, applicable attachments, lock/profile/adapter identity, selected target inputs and ownership manifests. Read each into bounded immutable buffers with content digests and identity checks; repeat inventory/identity/hash checks after capture. A mismatch schedules recapture, never publishes a torn snapshot. Use loader UTF-8 and symlink/containment gates. This is a logically consistent captured revision after stability checks, not an OS-wide transaction claim.
3. **Bind every stage.** Model/IR/graph/validation/drift/adapter stages consume that same captured set. Target adapters get immutable staged input plus original logical-path mapping and exact version/profile/lock pins; prohibit live-root rereads. Revalidate input inventory before committing a result. Editing during execution marks the run stale, cancels it and merges its dirty set into pending work.
4. **Compute changes.** Compare previous accepted and candidate inventories, retaining old owners/spans for removed paths; derive semantic seeds from typed old/new IR diff. An unchanged normalized semantic digest with changed source bytes updates source revision/span diagnostics while reusing semantic facts. Formatting-only changes from #94 are therefore visible as source changes without fictitious semantic changes.
5. **Select affected work.** Union old/new reverse dependency closures, direct owned symbols, policy/effect/scenario obligations, import dependents and mandatory public checks. Maintain input fingerprints per validation work unit and target operation; cache and replace graph fragments and affected IR resolutions. Resolution/import/global uniqueness rules have explicit scope dependencies. An unknown mapping, project-wide profile change or incomplete graph selects a reason-labeled full fallback, never an empty success. Module-only output is not selective execution evidence.
6. **Replace diagnostics by ownership.** Maintain the latest accepted diagnostic partition per rule/unit/target and merge recomputed partitions with untouched valid partitions. Remove resolved findings and orphan partitions. Invalid parse produces current source diagnostics and explicit unavailable downstream coverage; never relabel the last valid graph as current. A settled result contains the whole effective selected diagnostic set, not only additions. Superseded intermediate findings may be marked stale but cannot be silently dropped from an already emitted run.
7. **Invalidate dependents.** Content, core/schema/profile/adapter/lock updates invalidate linked parsed/IR/graph/target-evidence/capsule entries. Removal/rename removes old graph edges, owners, bindings and capsule dependencies before installing new facts. Semantic rename continuity requires accepted rename evidence; a filesystem move alone is not a symbol rename. No persisted binding proposals are confirmed by watch.
8. **Check generated drift without loops.** Cache/build roots (`.git`, `.lekalo/cache`, configured build output such as `target`, `node_modules`, `dist`) never trigger semantic runs. Access/metadata-only and identical-byte events are ignored. Generated artifacts under `.lekalo/generated` are excluded from Model/adapter scan inputs but, with `--generate-check`, watched for a hash-changing drift-only run; manifests/lock are governed metadata inputs. One editor save cannot start generation or repeatedly rerun on the watcher's own reads. Do not ignore an explicitly classified source merely because its directory name resembles build output; root ownership/config determines the exclusion.
9. **Recover.** Native overflow, ambiguous/unpaired rename, lost root watch, and polling discrepancy force bounded inventory reconciliation and a full fallback when scope is uncertain. Adapter crashes/timeouts are terminal component failures; the session stays alive, retries on the next affected save or bounded recovery schedule, and preserves other targets' results. Do not busy-retry an unchanged failing input.

Suggested hard limits, all explicit in session configuration and tested: one active run; 4096 distinct pending paths; 16 MiB queued serialized output; 4096 watched directories; 128 MiB captured input bytes with existing tighter per-source limits; 64 MiB retained result state. Crossing a pending-path bound collapses to an explicit full-rescan marker; if a complete bounded rescan cannot fit, report incomplete/denied coverage and stop or wait for input reduction. Never truncate diagnostics into a success. Include global cumulative work caps for repeated recapture and each graph traversal, reuse accepted graph bounds, and cancel CPU work cooperatively between bounded work units.

## Determinism strategy and event lifecycle

Use a monotonic run ID and source-generation counter; monotonic clocks govern debounce/deadlines only, never semantic digests. Stable snapshots have sorted logical input inventories, tagged changed-input rows (`created|modified|deleted`, rename links only when reliable), and explicit source-set/model/IR/graph/lock/profile/evidence digests. Git HEAD is optional provenance and insufficient for uncommitted edits; source-set digest identifies the revision. Project paths are logical relative paths, with no absolute host paths, repository URL, credentials, raw source, adapter stderr, or provider content in events.

Event vocabulary: `session-started`, `run-started`, `run-completed`, `run-cancelled`, `recovery-required`, `session-stopped`. Each union arm is closed with `additionalProperties:false`, bounded arrays/strings, checked cross-field consistency, and exact pins. Common members: `schemaVersion`, `identity`, `sequence`, `event`, `sessionId`; run arms add `runId`, `generation`, `sourceRevision` and stage-specific result/cancellation members. Completed results are whole replacements with `diagnosticsMode: replace`; cancelled runs carry `supersededByGeneration` and `committed:false`. Every started run gets exactly one terminal event, including on Ctrl-C. Sequence is strictly increasing per session; opaque session identity/clock fields are excluded when comparing deterministic semantic results.

Illustrative event skeleton, not a schema-valid golden (placeholders must be expanded by fixture generation):

```json
{
  "schemaVersion": "lekalo/watch-event/v0.8.0",
  "identity": "dev.lekalo.watch-event@0.8.0",
  "sequence": 4,
  "event": "run-completed",
  "sessionId": "<opaque-local-id>",
  "runId": 2,
  "generation": 3,
  "sourceRevision": "sha256:<captured-input-digest>",
  "diagnosticsMode": "replace",
  "result": "<closed watch-result object with component status and exact pins>"
}
```

Use the accepted diagnostic envelope for actual diagnostic rows. The stream schema fixes its diagnostic/result contract references; no free-form `metrics` or raw arbitrary adapter payload is allowed. Result rows distinguish executed/reused/not-requested/unavailable checks and complete/partial/unsupported coverage. A reused row carries the validated fingerprint and current revision binding; it does not claim a fresh adapter execution.

Cancellation sets the accepted adapter cancel flag, cooperatively stops core stages, kills/reaps owned children and verifies descendants are gone before starting a new adapter run. Stale work cannot mutate shared accepted state or emit `run-completed`; its dirty inputs remain pending. If stale teardown exceeds its deadline, report infrastructure failure and keep the latest batch queued rather than launching overlapping processes. Read-only stage failures do not end the session. A terminal input/backend refusal maps to the accepted `DomainResult` status/exit; normal Ctrl-C emits cancelled/stopped events and exits 0. Exit 0 on a running session does not certify every observed revision as valid.

All JSON Lines events, including invalid run results, go to stdout; stderr is reserved for bounded host/log messages without domain JSON. This is a new streaming transport, leaving existing single-command status-owned streams unchanged. Broken pipe/write failure terminates the session, cancels children and returns output failure 1. Bound producer queues; slow consumers must backpressure or terminate with an explicit failure while a stream is still writable, never silently discard completed diagnostics. Human output projects the same state with concise revision, changed-input count, selected/reused checks, verdict and diagnostics.

## Diagnostics (LEK-WATCH-*) proposal

Proposed allocations; check for collisions against the merged registry before implementation. Existing loader, lock, artifact, adapter, validation, and version diagnostics pass through unchanged; new codes describe watch lifecycle/coverage rather than duplicating domain findings.

| Rule ID | Code | Proposed status/severity and meaning |
| --- | --- | --- |
| `watch.backend-unavailable` | `LEK-WATCH-001` | unavailable/error when no requested backend can run; warning on a successful explicit auto fallback. Include bounded backend token. |
| `watch.event-loss` | `LEK-WATCH-002` | valid/warning during recovery; incomplete result until reconciliation succeeds. Include closed cause (`overflow|ambiguous-rename|subscription-lost|inventory-mismatch`). |
| `watch.snapshot-unstable` | `LEK-WATCH-003` | unavailable/warning for exhausted bounded capture attempts; no committed torn result. A newer dirty generation remains pending. |
| `watch.resource-limit` | `LEK-WATCH-004` | denied/error when a hard bound prevents complete safe work. Include bounded limit name and count, no raw path list. |
| `watch.selective-unavailable` | `LEK-WATCH-005` | valid/warning for a complete reason-labeled full fallback; unsupported or unavailable when required work cannot be run safely. Include closed stage/reason. |
| `watch.adapter-recovery` | `LEK-WATCH-006` | unavailable/warning for a failed target cycle with recovery scheduled; retain the adapter's original classified diagnostic. A successful later run removes the stale finding. |
| `watch.cancellation-incomplete` | `LEK-WATCH-007` | unavailable/error if owned work cannot be proven terminated within the deadline; no overlapping replacement run. |

Ordinary cancellation is an event, not an error code. Usage errors remain `cli.usage`, unsafe reads retain their owning security diagnostic, and output failure follows existing writer handling. Give each new registry entry exact message, category, allowed statuses, data fields, location policy and lifecycle. Extend registry consumers/normalizers and positive/negative coverage fixtures; update validation profiles/reports only if their closed registry binding changes. Preserve base/successor rule identities, tombstones and diagnostic limits. A limit failure must remain observable even when the normal producer diagnostic set exceeds its bound; use the accepted overflow/invariant handling rather than truncation.

## Risks and non-goals

- **Selective validation soundness:** rule fingerprints can miss indirect policies, attachments, imports or public obligations. Maintain explicit input dependencies and differential oracles; fallback is preferable to incomplete confidence, but repeated full fallback does not satisfy the isolated planner acceptance case.
- **Snapshot soundness:** filesystem notifications and two inventory passes are not an OS transaction. Immutable stage inputs, end-of-run revalidation and stale cancellation are essential; repeatedly unstable inputs remain visible instead of promoting old state.
- **Generated-output exclusion:** blanket ignoring `.lekalo/generated` would hide manual drift. Separate drift input watching from semantic/adaptor scan inputs and exclude the watcher's own derived/output work.
- **Adapter scope and custody:** current scan persists state and transport child kill does not by itself prove descendant termination or frozen-input access. Add and test safe seams; unsupported confinement stays unavailable, never a false cross-platform pass.
- **Rename/path behavior:** inode reuse, split events, case folding, Unicode normalization, Windows junctions and parent renames differ by backend/filesystem. Inventory and content determine current identity; preserve original logical spelling and detect collisions rather than guessing symbol continuity.
- **Resource and stream behavior:** editor floods, oversize trees and slow readers can lose event/diagnostic state unless queues and recovery are explicit. Bounds must fail observably, never silently truncate results or create unbounded retries.
- **Version/merge drift:** main is `0.6.5`, implementation target is `0.8.0`, and M8 dependency docs are absent. Recheck dependency/merged contract pins before implementation; maintain the complete registry/provider/profile union and freeze untouched schemas.
- **Non-goals:** auto-generation, formatter implementation, LSP server, cloud service/daemon, orchestration task dispatch, running native or production commands, lock/profile updates, artifact cleanup, binding promotion, durable history/export, and private-project benchmarking. Watch events provide local evidence for an IDE/agent; they grant no execution authority to consumers.
