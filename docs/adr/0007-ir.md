# ADR-0007: Typed deterministic target-neutral IR

Status: accepted for issue #8 (product candidate 0.1.6).

## Context

Issues #6 and #7 gave Lekalo stable semantic IDs and a capability-safe
loader that produces one canonical model with optional source spans. Every
downstream capability — validators, graphs, impact, context, adapters —
needs a typed, immutable read model instead of re-parsing source documents,
and the Model contract must stay the only source of shape truth.

## Decision

1. The IR is a Rust-first closed surface in `lekalo-core::ir` with contract
   identity `dev.lekalo.ir@0.1.0`. It is consumed from the loader's
   normalized aggregate (`loader::normalize_model`, extracted verbatim from
   the accepted #7 pipeline so `lekalo load` stays byte-identical). No JSON
   Schema artifact is published for IR 0.1.0; the canonical byte format is
   specified in `docs/ir.md` and pinned by frozen golden fixtures, because
   the IR is not a source format anyone authors — it is a compiled
   read model.
2. `Definition` is a closed Rust enum over the twelve symbol kinds and
   `EffectOperation` the closed `create`/`update`/`delete` enum; both are
   exhaustively matchable without wildcard arms, and tests enforce it at
   compile time. `project`/`module` become `Project`/`Module` structs with
   version-aware ID grammars.
3. `TypeRef` mirrors the accepted Model type grammar (`ref`, `list`,
   `optional`, depth ≤ 4). The issue language mentions map and result
   types; they do not exist in any accepted Model version, so the IR
   deliberately omits them rather than representing models no source can
   declare. They require a reviewed Model successor first.
4. Extensions fail closed. Unknown keys are `ir.unknown-field`; there is no
   namespaced extension container in IR 0.1.0 because no accepted source
   Model version can carry one. The container arrives only with a reviewed
   IR contract successor tied to a Model successor that defines real
   extension keys.
5. Canonical bytes: compact UTF-8 JSON, unsigned UTF-8 byte-ordered keys,
   semantic-ID-ordered set-like arrays, source-order preservation for
   semantically ordered arrays, and loader-identical string escaping. Empty
   optional arrays normalize to absent. The IR's canonical definition
   objects intentionally align with the loader's canonical model objects
   because both apply the same byte-order rule to the same closed shapes.
6. The source map is separate from the semantic payload: occurrence-safe,
   sorted by `(path, pointer, startByte)`, with entries for definitions,
   keys, array members, and every type-expression node — richer than the
   #7 CLI map (which only records module crumbs), because the IR decodes
   the spanned trees directly.
7. Diagnostics: a closed `ir.*` prefix (`unknown-field`, `missing-field`,
   `kind-placement`, `kind-unknown`, `value-invalid`, `duplicate-member`)
   reusing the loader diagnostic wire shape, sort order, bound, and the
   accepted 0/1/3/4/5 exit envelope. Any diagnostic fails the entire
   compilation.
8. CLI exposure is a `--ir` flag on `lekalo load` rather than a new
   subcommand: IR is the next pipeline stage of the same ingest command,
   the default path stays byte-identical, and `--spans` composes naturally.

## Consequences

Downstream issues consume `CompiledProject` plus `SourceMap` instead of
parsing source; cache keys can bind the canonical IR bytes; graphs build
from typed references. Reserved-word checks, reference target/kind
validation, and identity membership remain with the Model validator and
semantic validation, so the IR never becomes a second authority. Adding an
IR node kind, a type wrapper, or an extension container is a breaking
contract successor, not a patch.
